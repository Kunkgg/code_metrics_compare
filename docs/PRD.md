## 2. 问题、目标与成功标准

### 2.1 当前问题

1. 结果分散在多个 Excel 中，用户需学习表结构并手工筛选、排序和跨表关联。
2. 重复代码增长只能先定位文件，再查扫描明细和重复组，才能找到相关片段。
3. 超大目录仅有数量，缺少可直接查看的成员与覆盖说明。
4. 文件代码行、重复代码行、函数代码行、圈复杂度缺少目录分层聚合。
5. 文件路径与函数名作为匹配键时，同文件同名函数可能产生多对多全排列，放大或伪造变化。
6. 空值、扫描范围或阈值变化若被当作零值或代码变化，会误导恶化判断。

### 2.2 产品目标

- **G-01 发现变化：**在统一报告中识别看护指标增长及相关目录、文件和函数。
- **G-02 取得定位证据：**将变化与函数位置、重复片段、问题记录或目录成员关联，减少人工跨表拼接。
- **G-03 避免错误结论：**区分可比变化、未知、歧义及扫描记录进出，使证据限制可见。
- **G-04 便于内部交付：**在目标规模下生成可独立分发、断网双击阅读的单 HTML。

产品的任务终点是“取得足够的定位证据”。它不自动判断真实质量根因、责任人或处理结论；用户仍需转到现有 IDE 或代码平台检查源码。

### 2.3 成功标准

- 第 10 节五项业务任务全部正确完成，无需人工跨多个结果表拼接信息。
- 第 9 节离线、安全、容量和性能要求全部通过；不得以静态概览可读替代交互验收。
- 对照现有 Excel 流程记录任务步骤与耗时；当前不设未经测量的效率提升比例或 ROI。
- 原型通过不等于正式交付；公司内部代表性真实数据核验是交付必要条件。

## 3. 用户、使用场景与流程

### 3.1 用户角色

| 角色 | 核心任务 | 产品内任务终点 |
|---|---|---|
| 质量看护人员 | 比较同一代码库两次扫描，发现增长、定位主要变化对象，检查结论可信性 | 得到需评审的指标与相关对象，以及数据质量和可比性说明 |
| 组件接口人／开发人员 | 检查函数变化、重复关系、问题位置和目录成员 | 取得可复制的路径、标识、位置和度量证据，转到现有工具检查 |
| 报告生成者 | 选择两份扫描 JSON，提供可选代码元信息，生成并分发报告 | 得到完整报告或明确失败诊断；不需要管理后台 |

角色可以由同一人承担。报告阅读者不需要 Python，也不需要安装其他软件。

### 3.2 主流程

```text
生成者指定 baseline/current JSON、输出位置及可选元信息
  → 校验、适配、身份匹配、对比及聚合
  → 生成正常报告／受限报告，或失败并提供诊断
  → 阅读者断网双击 HTML
  → 概览确认扫描身份、可比性和指标变化
  → 选择指标，按目录与文件下钻
  → 查看函数、重复组、问题记录或超大目录成员
  → 复制定位信息，在现有 IDE／代码平台继续排查
```

“受限报告”是可明确界定局部异常影响时的有效交付形态，不得伪装成所有分析均成功。正常与受限报告的发布规则见 FR-02、FR-16。

## 4. 首期范围与非目标

### 4.1 必须交付的能力

- Python CLI：一次处理 baseline/current 一组扫描，不以 Excel 为输入契约。
- 单 HTML：资产与运行所需数据全部内嵌；桌面 Chrome / Edge 真实 `file://` 运行。
- 覆盖第 7 节全部 13 类结果，但不要求对应 13 个页面。
- 概览、目录／文件分析工作区、对象详情、数据质量与报告说明。
- 文本搜索、范围筛选、数值筛选、排序、有限记录展示及完整范围查询。
- 文件／函数／重复片段等关联定位、可复制定位文本。
- 全部必要变化信息、关联上下文、异常诊断及未变化数据省略说明。
- 预生成的静态概览，以及交互初始化失败时的可读兜底。

### 4.2 首期不做

- 图形化生成器、浏览器上传解析、批量多仓库任务、Excel 输入兼容。
- 本地服务、在线平台、多人协作、账号权限、历史趋势、CI 阻断或质量门禁。
- 自动归因、责任人定位、审批、原因填写、批注或评审备案存储。
- CSV／Excel／PDF 导出、IDE 自动跳转、跨会话保存分析状态。
- 嵌入源码正文、自动读取本地代码库、搜索源码内容。
- 文件重命名／移动追踪、同名函数猜测配对、重复组跨版本身份追踪。
- 正则表达式、SQL、多条件查询编辑器、自定义仪表盘。
- Treemap、关系网络、火焰图；不承诺移动端或未测试浏览器／OS 组合。
- CCA、函数深度、抑制告警等新增看护指标；不得因输入有字段而自动扩展范围。

### 4.3 不得隐性降级的约束

目标规模无法达标时，必须暂停并重新评审。不得静默丢弃必要变化、隐去歧义、仅保留 Top N、以当前页冒充全局查询，或自行改成多文件／服务端交付。修改约束须再次取得需求方确认。

## 5. 指标白名单与比较规则

### 5.1 概览的 13 项主指标

主指标均显示 baseline、current、差值、单位、数据来源及可比性。对有效且可比的主指标，正差值按公司口径标记为“增长／待评审”；这不等于工具已证明实际质量下降。

| 编号 | 看护指标 | 汇总字段 | 单位 | 主要下钻方向 |
|---|---|---|---|---|
| M-01 | 非空非注释代码量 | `code_size` | 有效代码行 | 目录、文件 |
| M-02 | 平均文件代码行 | `lines_per_file` | 有效代码行／文件 | 文件总量与文件数、目录和文件 |
| M-03 | 平均函数代码行 | `lines_per_method` | 有效代码行／函数 | 函数总量与函数数、目录／文件／函数 |
| M-04 | 平均圈复杂度 | `cyclomatic_complexity_per_method` | 复杂度／函数 | 复杂度总量与函数数、目录／文件／函数 |
| M-05 | 代码重复率 | `code_duplication_ratio` | % | 文件重复行数、重复组与片段 |
| M-06 | 文件重复率 | `file_duplication_ratio` | % | 重复文件成员 |
| M-07 | 危险函数 | `unsafe_functions_total` | 去重位置数 | 文件、危险函数名、行号 |
| M-08 | 冗余代码 | `redundant_code_total` | 代码块数 | 文件、块起始行 |
| M-09 | 超大圈复杂度 | `huge_cyclomatic_complexity_total` | 函数数 | 超限函数 |
| M-10 | 超大函数 | `huge_method_total` | 函数数 | 超限函数 |
| M-11 | 超大头文件 | `huge_headerfile_total` | 文件数 | 超限头文件 |
| M-12 | 超大源文件 | `huge_non_headerfile_total` | 文件数 | 超限非头文件 |
| M-13 | 超大目录 | `huge_folder_total` | 目录数 | 直接子项数量及扫描可见成员 |

**支撑度量白名单：**除上述 13 项主指标外，以下 20 个 `summary_metrics` 字段属于首期支撑数据，须可查看两侧有效原值及有意义的差值；缺失或不适用时按第 5.2 节说明状态，不自动补值。它们不自动获得主指标的待评审规则。

| 支撑字段 | 单位／用途 |
|---|---|
| `raw_lines` | 物理总行数，区分有效代码行与文件总行 |
| `files_total` | 文件数，文件均值及相关比例的分母 |
| `folders_total` | 目录数，超大目录比例的分母 |
| `methods_total` | 函数数，函数均值及相关比例的分母 |
| `method_lines` | 函数有效代码行总量，解释平均函数代码行 |
| `cyclomatic_complexity_total` | 普通圈复杂度总量，解释平均圈复杂度 |
| `maximum_cyclomatic_complexity` | 普通函数圈复杂度最大值 |
| `huge_cyclomatic_complexity_ratio` | %，超大圈复杂度函数比例 |
| `huge_method_ratio` | %，超大函数比例 |
| `huge_headerfile_ratio` | %，超大头文件占全部文件比例 |
| `huge_non_headerfile_ratio` | %，超大非头文件占全部文件比例 |
| `huge_folder_ratio` | %，超大目录比例 |
| `file_duplication_total` | 重复文件成员路径并集的文件数 |
| `non_hfile_duplication_total` | 重复文件成员中的非头文件数 |
| `non_hfile_duplication_ratio` | %，上述非头文件数占全部文件比例 |
| `code_duplication_total` | 文件有效重复行数之和 |
| `non_hfile_code_duplication_total` | 非头文件的有效重复行数之和 |
| `non_hfile_code_duplication_ratio` | %，上述重复行数占全部有效代码行比例；真实尺度仍须核验 |
| `unsafe_functions_kloc` | 每千有效代码行的危险函数去重位置数 |
| `redundant_code_kloc` | 每千有效代码行的冗余块数；适用低代码量特殊规则 |

13 项主指标与 20 项支撑字段合计构成 33 项数值汇总白名单，对齐生成指导 §4 的字段表，但不把模拟公式自动扩大为真实输入保证。白名单之外的数值字段不自动纳入分析。支撑数据可在详情中查看，不要求新增 20 个主指标卡片。

另将 `method_metrics` 尾对象的 `maximum_nbnc_loc` 列为必要明细支撑值，用于展示和校验函数有效代码行最大值；它不计入 33 项汇总，也不是新增主看护指标。尾对象的 `maximum_cyclomatic_complexity` 与同名汇总值及普通函数实际最大值分别核对，不重复计为指标。对象层面的文件代码行、重复行、函数代码行与圈复杂度变化仍须展示，支持已确认的下钻任务。

不生成综合质量分数。数量下降但比例上升等情况分别展示，不互相抵消。两项 `warning_suppression_*` 均不分析、不生成、不参与统计一致性校验，也不填为零；输入保留仅为结构兼容（可选解析，不阻塞流程）。

**数值计算与精度基线（G0 固定）：**
- **浮点与除法精度：**所有均值、比例、密度运算先使用原始整数比或未舍入浮点数进行，最终展示舍入采用十进制 Half-Up（四舍五入），最多保留 6 位小数。
- **零分母与异常值：**分母为 0 时统一按合成约定输出 `0`，并在报告界面与指标卡中明确标注状态为 `分母为零/不适用`；严禁生成 `NaN` 或 `Infinity`。
- **密度指标特殊规则：**`code_size < 1000 → 0` 的特殊规则仅适用于 `redundant_code_kloc`；`unsafe_functions_kloc` 等其他密度指标严格执行除法运算。

### 5.2 值与状态必须分离

| 状态 | 含义 | 对比处理 |
|---|---|---|
| 已观测数值 | 输入提供有效值 | 口径及单位一致时可计算差值 |
| 不在扫描集合 | 完整性与成员证据支持缺项 | 仅对允许零基准的总量按零计算集合进出，并保留缺项来源 |
| 对象存在但无该问题 | 完整问题清单支持无记录 | 对应问题数可为零，不等于文件不存在 |
| 对象存在但未超限 | 未进入超限清单 | 从完整明细回补数值；不可回补时仅显示清单进出 |
| 未知／无效 | 缺失、解析异常、覆盖不明等 | 不填零，不给出受影响数值的确定差值或改善结论 |
| 匹配歧义 | 无可靠一一配对 | 保留两侧记录，不输出确定的逐对象差值 |

- `delta = current - baseline` 仅用于已知、同口径同单位的值，或按上述规则明确赋零的值。
- 正常空容器、缺失字段与 `null` 不等价；函数空集合的表示见第 6.2 节。
- 数据有效性与可比性独立表达。两侧原值可读不等于可作业务判断。
- 已知规则、阈值、版本或范围差异影响的指标标为“不可直接比较”；元信息不足标为“可比性未验证”。可以保留有意义的观测差值，但不得标成可靠恶化／改善结论。
- 比例显示两侧百分数及百分点差值；首期不以相对增长率代替绝对差值。显示舍入不得改变判定精度，小幅增长显示近零时须能查看足够精度并解释标记。
- 危险函数、冗余代码等位置记录统一称“扫描记录新增／消失”，不称已证实的“问题新增／修复”。文件路径进出也不证明磁盘文件真实新增／删除。

### 5.3 聚合与统计规则

- 常规目录聚合覆盖后代文件；超大目录直接子项计数不递归，两种口径分别命名。
- 可加总量按两侧分别聚合再求差值，保留有效对象数、增长／减少及歧义数量；目录净零不能掩盖内部变化。
- 平均值、比例根据对应总量和分母重算，不平均已有平均值，不相加比例。平均值和比例变化不能直接分摊为各子项差值的简单和。
- 文件代码行与重复代码行分别使用 `file_sizes[path][0]`、`[2]`；重复组片段长度之和不能替代文件重复行数。
- 全局扫描汇总原值与明细派生值分别标识。若不一致，展示冲突及影响，不强制对齐，不静默择一作为已验证事实。
- 缺项或未知导致的部分聚合须标明覆盖范围，不冒充完整总量。裁剪后的剩余列表不能用来重算原始总体均值。
- 公式与分母参考生成指导 §4；其中百分数尺度、零分母及其他合成约定对真实输入的适用性仍须核验。

## 6. 输入、身份与可信性边界

### 6.1 输入与兼容范围

- 输入为同一代码库的 baseline/current 两次全量扫描 JSON，包含 `summary_metrics` 和 `detail_metrics`；不是只扫描改动文件的增量结果。
- 首期范围为 C/C++（`clike`）和已定义的 POSIX 路径形式。真实支持版本及差异须在内部核验后登记；不宣称覆盖全部 Cmetrics 版本。
- 支持恰一个 `-fp` 参数，其值为一个或多个逗号分隔的绝对扫描目录，并包含 `-l clike`。命令仅解析和展示，永不执行。
- 首期不支持相对路径、引号包裹、路径本身含逗号、控制字符、多个 `-fp`、`.`／`..` 段、重复斜杠、符号链接解析或 Windows 风格扫描路径；超出范围显式报错，不猜测、不依赖源码文件系统。
- 每侧从扫描路径集合按路径段计算公共根，再得到仓库相对路径。不得按字符公共前缀截断或盲目转小写。
- 明细须位于声明扫描范围内。路径规范化碰撞、根外路径、无可用公共根及两侧根层级改变导致的映射问题必须显式诊断；不能静默解释为大批新增／删除。
- **扫描根路径层级漂移处置：**若 baseline 与 current 提取的公共根目录层级不一致（导致相对路径命名空间不对齐），报告生成器应判定为局部阻断（FR-02），发布受限报告：
  1. 概览区与顶部全局 Banner 明确提示：`扫描根路径不一致，文件级对比已降级`；
  2. 停止计算文件级与函数级的跨版本差值，仅展示各侧自身聚合总量；
  3. 禁止将路径结构平移静默识别为 100% 文件删除与 100% 文件新增。
- 输入路径约束不限制报告在 Windows 浏览器中阅读；浏览器／OS 支持以实际验收矩阵为准。
- 原始键、历史输出表名及拼写差异必须通过显式适配映射处理，不自动将近似拼写认作同义。模拟 Schema 的严格未知字段规则不直接充当所有真实版本的兼容策略。

### 6.2 关键字段与实体身份

| 对象／字段 | 必须遵循的规则 |
|---|---|
| 文件 | 使用规范化的仓库相对路径匹配；不追踪移动／重命名 |
| 函数 | 经验证的稳定身份可用于匹配；只有路径和函数名时，键在两侧均唯一才配对。任一侧同名冲突均隔离为歧义，不按行号强配，不生成笛卡尔积 |
| `file_sizes` | 三元数组依次为有效代码行、物理总行、文件有效重复行；不得调换或用片段长度替代第三项 |
| `method_metrics` | 唯一最大值对象必须位于末尾，包含 `maximum_cyclomatic_complexity`、`maximum_nbnc_loc`，且值与普通函数一致；不得计为函数 |
| 无函数 | 数组仅含上述最大值对象，两项均为 0，不是空数组；不由此推断其他零分母行为 |
| 重复组 | 组身份限定于所属扫描；两侧相同编号不等于同一组 |
| 重复片段 | 使用路径、`start_line`、长度 `code_duplication` 定位；不依赖可选 `end_line`，不由长度反算物理结束行 |
| 危险函数 | 粒度为 `(文件, 危险函数名, 行号)`；同文件同名同一行去重，不同名称同一行分别计数 |
| 冗余代码 | 数组条目为代码块起始行；数量单位是块，不是代码行；不擅自套用危险函数的去重规则 |
| 超限对象 | 文件代码行、函数代码行和圈复杂度按各侧生效阈值严格 `>` 派生，不要求扫描器额外输出四类超限清单 |
| 超大目录 | 输入给出直接子项数，成员从完整文件集合恢复；只承诺扫描可见成员，不承诺磁盘完整目录 |

同名函数无法配对时，两侧有效原始值仍可各自聚合；逐函数解释须显示匹配覆盖率，不能用歧义配对结果解释整体差值。

### 6.3 代码元信息与可追溯性

baseline/current 分别允许手工提供仓库、分支、节点、版本号，全部可选。“节点”为 commit ID 或 revision，与可读版本号分开。未填显示“未提供”，不从文件名推断；来源标为“用户提供、未验证”。

扫描工具版本来自 `cmetrics_version`，不是代码版本。代码版本不同不构成不可比理由；可比性检查针对工具版本、各项阈值、语言、扫描范围及可获得的规则。不同检出根导致命令字符串不同，不应仅按文本不等判断不可比；文件集合变化本身也不是扫描范围定义不一致。

报告须记录生成器版本、报告数据格式版本、输入摘要标识、各侧扫描元信息、有效／异常记录数量、匹配覆盖及保留／省略范围。输入摘要用于追溯，不证明输入来源可信。

### 6.4 校验分层与不能证明的事实

沿用生成指导的 L0–L3：L0 检查 JSON 与重复键／非标准数值；L1 检查结构；L2 检查末尾对象、引用、命令、公式及阈值等语义；L3 仅检查生成器内部有效行、重复覆盖及变化台账。

模拟生成器的正常输出须通过相应分层校验；错误夹具必须单独标记。真实输入采用经核验的版本适配与语义规则，不能因模拟 profile 校验通过就宣称真实口径已验证。

仅凭片段起点与有效长度通常无法重建有效重复行并集。外部输入只能复核文件重复量与汇总等可证关系，不能宣称已验证真实重复覆盖。其他尚未核验事实见第 12 节。

## 7. 功能需求与结果覆盖

以下 FR 均属于首期必须需求，除非条目明确说明条件；实现顺序不改变正式交付范围。

### FR-01 报告生成

使用者通过 Python CLI 指定两份 JSON、输出位置及可选两侧元信息，一次生成一个 HTML。输入中 baseline/current 身份必须显式指定，不由文件名猜测。生成过程提供阶段／执行状态及失败原因。

最终产物必须在必要校验完成后发布；生成中断或失败不得留下被误认为成功报告的半成品。参数名称、安装方式和内部数据格式在技术设计中确定，不在 PRD 中冻结。

**验收：**同一组输入可重复生成语义一致的结果；交换两侧后，有效同口径数值的差值方向正确反转；报告阅读不依赖输入 JSON 仍在原位置。

### FR-02 分级校验与处理结果

- 全局阻断：无法解析、顶层核心结构损坏或无法建立可靠全局路径映射时，不发布正常对比报告，提供可定位的诊断。
- 局部阻断：可界定影响范围时停止相关处理，保留其他可靠结果并发布受限报告；不能隔离的错误须提升为全局阻断。
- 局部未知／歧义：不得补零、任选配对或隐去；受影响模块明确不可得的结论。
- 正常空结果：显示“无变化／无记录”等符合实际范围的状态，与异常空白区分。

**受限报告 UI 规范：**
- **全局警示 Banner：**固定在页面顶端醒目位置，黄色（局部阻断／警告）或红色（严重限制），写明受限原因（如：`圈复杂度函数匹配存在歧义，部分逐函数差值已屏蔽`）及受影响的模块范围。
- **受影响模块标记：**受影响的下钻入口保留但附带 `[受限]` 标签，点击进入后首先展示限制说明面板与各侧原始数据，不展示未经证实的确定性差值。

**验收：**错误包含扫描侧、字段或对象、原因及影响范围；第 5.2 节状态可区分；受限报告的概览和受影响模块均提示限制。

### FR-03 可信匹配与比较

按第 6 节建立文件、函数及位置记录的身份；合并前检查键基数，先校验、匹配、聚合和关联，再裁剪数据。各类差值遵守第 5 节规则。

**验收：**同名函数不产生笛卡尔积；根层级变化不被静默误识别为文件变化；行号移动可产生位置记录进出，但不会自动标为问题真实新增／修复。

### FR-04 概览

提供 13 项主指标、有效支撑数据、两侧代码与扫描身份、可比性以及关键数据质量提示。主指标可进入对应分析范围；数据不可用时进入原因说明，不提供伪造的下钻结果。

**验收：**13 项主指标、20 项汇总支撑字段及必要明细最大值按第 5.1 节覆盖，数值、来源及单位准确；缺项状态可见，不补造数据；抑制告警不进入分析；扫描汇总与明细派生冲突可见；不出现综合质量分数。

### FR-05 目录分析与基础图表

提供目录树、路径上下文及层级下钻。文件代码行、重复代码行、函数代码行、圈复杂度均支持目录聚合，展示两侧总量、差值和有效对象数量；涉及均值／比例时展示相应分母和口径。

以指标概览、目录树和可排序表格为主，提供可加总量的增长／减少条形图。图表可限定显示前若干项，但必须说明指标、范围、排序及截取数量，并可进入完整保留记录列表。目录净零但内部有变化时仍可下钻。

**验收：**父目录在完整可加总集合上与后代贡献一致；未变化记录的聚合贡献未丢失；超大目录直接子项不混作递归总量；均值和比例不使用子项差值简单相加的贡献图。

### FR-06 文件分析

显示文件相对路径、各侧存在性、有效代码行与重复行的原值及变化；同一文件可进入函数、重复组、危险函数和冗余代码等关联明细。路径进出使用扫描集合语义。

**验收：**无重复问题与文件不在扫描集合可区分；文件其他度量或关联结构发生变化时，不因当前单一度量差值为零而被删除。

### FR-07 函数分析

在目录／文件范围内查看函数代码行与圈复杂度，可展示两侧函数名、位置、原值、差值、超限状态及匹配状态。普通函数起止行用于定位，不作为未经验证的跨扫描稳定身份。

**验收：**唯一键变化可定位；同名歧义可查看两侧原始记录及原因；最大值对象不出现在函数列表或函数计数中；聚合与逐函数解释覆盖分开说明。

### FR-08 重复代码联查

从文件重复行变化进入 baseline/current 各自的重复组，再查看组内所有相关片段的文件、起始行及长度。允许查看未增长文件中的必要关联片段；不按跨扫描组编号相同建立身份对应。

**验收：**重复增长文件可沿报告内关联找到其他相关片段，无需人工跨表检索；裁剪不切断组关系；片段数值和定位不依赖反算结束行；重复量以文件字段为准。

### FR-09 重复文件分析

显示文件进入／退出重复文件记录集合及两侧组成员上下文。统计按成员路径并集，不将组数或组内重复出现次数当作重复文件数。

**验收：**文件在多个组中不重复计数；无重复记录和不在文件集合可区分；两侧编号变化不被解释为稳定组身份变化。

### FR-10 危险函数分析

按文件、危险函数名、行号展示位置记录及进出。汇总为各文件、各名称下去重行号数组长度之和；同一行不同危险函数分别保留。

**验收：**一个位置不被还原为同一行的多次调用；同名多位置变化不被文件级或名称级匹配吞掉；定位文本说明这是去重位置记录。

### FR-11 冗余代码分析

按文件与代码块起始行展示记录及进出，提供定位信息。数量表示块数，不表示冗余代码行数。

**验收：**起始行移动不被描述为已证实的问题修复／新增；原始条目及统计处理采用已验证口径，不擅自去重。

### FR-12 四类文件／函数超限分析

从完整文件／函数明细和各侧阈值派生超大头文件、超大源文件、超大函数、超大圈复杂度函数。展示清单进入／退出、可取得的两侧数值及阈值。

**验收：**等于阈值不超限，严格大于才超限；退出清单仍显示可回补的实际值，不补零；两侧阈值不同不被解释为可靠代码恶化结论；函数歧义规则同 FR-07。

### FR-13 超大目录分析

展示两侧扫描提供的直接子项数，以及由文件路径恢复的直接文件、直接子目录列表。直接子目录去重，不递归将后代文件列为直接成员。

**验收：**扫描数量与可恢复成员数分开展示，差异及覆盖限制明确；不补磁盘空目录，不宣称拥有完整本地目录；必要成员名称与类型不因度量未变化而被裁剪。

### FR-14 统一搜索、筛选与排序

- 默认显示全部变化及异常记录，可比的正向变化优先；数值不变但可观测结构／位置变化的记录仍保留。
- 歧义、未知和不可比有醒目提示及独立筛选入口；不能因为没有可排序数值而消失。
- 可选择当前目录及其后代或全报告范围；在适用列表中按路径、函数名等标识进行文本搜索。
- 可对适用的 baseline、current、差值排序或设数值范围；可筛选增长、减少、扫描集合进出、结构／位置变化和异常状态。
- 状态维度不得互相混淆：例如对象可以同时为扫描集合移入和数值增长。筛选结果须解释当前条件与范围。
- 搜索、筛选和排序必须覆盖声明范围内全部保留的可检索记录，不仅当前页或已加载部分。全报告搜索不包含未保留明细或源码正文，须明确提示。
- **可检索字段白名单与索引：**全报告文本搜索的检索字段严格限定为：**文件相对路径**、**函数名称**、**危险函数名称**、**超大目录路径**。不提供对扫描命令全文、未保留代码片段的全文模糊匹配。Python 生成端在预处理阶段对上述标识符构建紧凑的扁平字典索引，前端 Worker 直接基于预建索引匹配，确保大容量下检索耗时满足门槛。
- 展示命中数量、当前条件及省略说明；主动筛选排除异常记录时，仍保留该范围存在异常的提示。
- 长操作有执行反馈；首次返回部分结果时不得冒充最终全范围结果。有限展示方式可采用分页或虚拟列表，具体实现待验证。

**验收：**跨页／跨数据块命中、排序和数量与全范围预期一致；切换目录、返回概览或清除条件后不会沿用未显示的旧条件；正常无匹配与查询失败可区分。

### FR-15 定位信息复制

支持复制路径及定位文本。定位文本按对象类型包含可取得的扫描侧别、路径、函数标识／重复组、行号、片段长度和相关度量；歧义或未知须随文本说明。

**定位信息复制标准文本规范：**
- 普通函数度量示例：`[CMP-LOC] Side: Current | Path: src/core/main.c | Line: 120 | Symbol: parse_token | Metric: cyclomatic_complexity=25 (Baseline=18, Delta=+7, Status: Growth)`
- 重复代码片段示例：`[CMP-LOC] Side: Baseline | Path: src/util/helper.c | StartLine: 45 | DuplicationLength: 18 | Group: group_1`
- 危险函数位置示例：`[CMP-LOC] Side: Current | Path: src/net/socket.c | Line: 88 | Symbol: strcpy | Issue: unsafe_function (Status: Added)`
- 冗余代码块示例：`[CMP-LOC] Side: Current | Path: src/ui/view.c | StartLine: 210 | Issue: redundant_code_block (Status: Added)`

**验收：**baseline/current 信息不会混淆；不能自动复制时可手动选择完整文本；不触发 IDE、不读取源码、不执行输入命令。报告本身是完整分发载体，不新增导出格式。

### FR-16 数据质量与报告说明

提供集中说明区，列出输入身份、校验结果、可比性、匹配覆盖、记录数量、裁剪范围、统计口径和已知限制。严重问题同时出现在概览及受影响结果旁，不能只藏在说明页。

**验收：**用户能判断报告是正常还是受限、哪些结论不可得、哪些数据未保留；不能从某个“校验通过”推导成 L0–L3 或所有真实语义均通过。

### FR-17 离线阅读与静态兜底

报告通过真实 `file://` 打开，所有交互资产和数据均自包含。JavaScript 被禁用时，至少能读取预生成的概览、扫描身份及关键数据质量提示，并知晓交互不可用；初始化失败须显示错误及不可用功能，不长期停在伪加载完成状态。

**验收：**无网络、干净缓存下交互正常；禁用脚本或模拟初始化失败时静态内容仍可读；空白明细不会被表示为无变化。只有交互正常加载后才表示支持搜索、筛选和下钻。

### FR-18 必要数据保留与省略透明化

先完成校验、匹配、聚合及关联，再省略真正不需展示的未变化明细。保留全部必要变化、异常、关联上下文及导航信息，并保留被省略对象的数量和聚合贡献。

**数据保留三级优先级（Tiering）：**
- **Tier 1（核心必须，绝对不裁剪）：**所有发生数值增长／减少的指标对象、状态异常对象、歧义对象、目录聚合贡献及全局汇总。
- **Tier 2（强关联上下文，优先保留）：**重复代码增长文件所属重复组的全部相关片段、超大目录直接可见成员。
- **Tier 3（辅助参考，按需压缩保留）：**数值未变但位置移动的普通函数、无增减的独立重复组成员。
- **容量保护策略：**当极端变动（如接近 100% 变动）导致内嵌数据逼近 200 MiB 门槛时，生成器在保留 Tier 1 与 Tier 2 的前提下精简 Tier 3 辅助数据，并在数据质量说明区输出明确的《数据保留率与裁剪声明》，严禁静默截断必要核心数据。

零差值不是唯一的未变化判据。必要重复组成员、超大目录成员、其他度量变化、结构／位置变化与歧义记录均不可仅因某一差值为零而删除。仅有总量而无法识别结构变化时，说明能力限制，不能宣称完全未变。

**验收：**裁剪前后汇总和有效对象计数守恒，必要关联可达；报告明确省略范围；未保留明细不可展开或检索的限制准确可见；不得为体积达标静默截断必要数据。

## 8. 信息组织与竞品借鉴取舍

### 8.1 三个功能区

1. **概览：**扫描身份与关键提示在前，13 项主指标及支撑数据在后；从指标进入相关分析。
2. **分析工作区：**目录导航、当前范围、指标／对象切换、变化图表和明细；从文件继续查看对象详情及关联上下文。
3. **数据质量与报告说明：**集中提供诊断、覆盖、保留策略和口径；与概览及明细中的就地提示相互关联。

这些是功能分区，不指定前端路由、组件框架或弹窗形式。baseline/current 标识、单位、变化状态和当前过滤范围须持续明确；状态不能仅靠颜色表达。

### 8.2 从竞品研究提炼的产品要求

| 借鉴来源 | 采用的产品行为 | 不随之采纳的内容 |

| lizard | 交互失败时保留可读内容并明确降级 | CDN 依赖及断网放弃正常交互 |

## 9. 非功能需求与性能门槛

### 9.1 规模与性能（NFR-01）

目标规模为 baseline/current **每侧** 2,500 万有效代码行、10 万文件、100 万函数。两侧必须同时达到文件／函数规模；重复组、位置记录、长字符串和上下文分布也须纳入测试，不以行数单独保证容量。

| 项目 | 验收门槛 |
|---|---|
| 参考设备 | 4 核或以上 CPU、16 GB 内存、SSD |
| 浏览器 | 桌面 Chrome / Edge，均须测试并固定版本 |
| 最终单 HTML 体积 | ≤ 200 MiB，含静态概览、资产、数据和索引 |
| 打开至概览可操作 | ≤ 10 秒；仅静态内容出现不算可操作 |
| 常用目录下钻、分页、已有索引的筛选排序 | P95 ≤ 1 秒 |
| 跨全报告搜索等较重操作 | P95 ≤ 3 秒，执行期间有反馈 |
| 报告新增的浏览器峰值内存 | ≤ 2 GiB，包含页面、Worker 及实际使用的 WASM 等相关开销 |
| Python 报告生成耗时 | ≤ 10 分钟，从读取两份输入至最终 HTML 写完 |
| Python 报告生成峰值内存 | ≤ 8 GiB |

MiB／GiB 使用二进制单位。历史“5 万文件约 150 MB”只是用户容量参考，不是线性预测或产物预算依据。模拟生成器的预演目标另见生成指导，不得用数据生成耗时或内存冒充报告生成验收。

**测量要求：**记录 CPU、OS、浏览器、依赖版本、数据种子、配置、缓存状态及任务集；P1 前固定测量工具和重复采样次数。冷／热查询分别记录，P95 不混用口径。浏览器内存以干净会话为基线测增量，不能只用 JS heap 代替完整开销；同时记录概览可操作与数据初始化完成时间。

### 9.2 离线与兼容（NFR-02）

- 断网、干净缓存、真实双击 HTML；不以 `localhost` 测试替代验收。
- 不依赖 Python、服务、CDN、遥测、外部字体、旁置文件或隐式扩展下载；不得要求关闭浏览器安全策略。
- 正式支持仅限验收记录中的浏览器／OS 组合。P1 前固定实际 OS 矩阵，不把开发机通过扩大为所有平台保证。
- 不支持的能力、数据块损坏、内存不足及查询失败应尽可能给出可读错误；静态兜底不能掩盖交互验收失败。

### 9.3 安全与保密（NFR-03）

- 开发以合成数据为主，真实核验在公司受控环境完成；不要求上传公司材料。
- 路径、函数名、分支、版本和命令均按不可信文本处理，不得注入可执行 HTML／脚本；覆盖 `</script>`、特殊字符及模板注入测试。
- 扫描命令禁止执行，输入路径不得触发源码读取或任意文件访问。
- 报告仍可能包含敏感路径、标识和度量，沿用公司存储与分发规范；单文件不提供访问控制、撤销或保密保证。
- 固定并登记第三方依赖版本及许可证，检查最终产物无外连；浏览器或内嵌依赖升级后回归真实 `file://` 路径。

### 9.4 正确性、可恢复性与可理解性（NFR-04）

- 输入错误、局部受限和正常无结果的呈现遵守 FR-02，不发布看似完整的缺项结论。
- 长操作显示执行状态，查询结果范围与数量可核对；不能用加载动画掩盖无限等待或失败。
- 中文为主要界面语言，字段标识和代码名称保持原文；单位、侧别、状态采用文字说明，不依赖用户记忆颜色。
- 报告为静态快照，修正输入、元信息或对比逻辑后重新生成；不回写输入或保存跨会话状态。

## 10. 验收任务与测试覆盖

### 10.1 五项业务任务

在有明确预期结果的夹具上执行，并在公司内部代表性数据上补验。五项全部通过；记录完成路径、步骤、耗时及用户是否误读结果，与原有 Excel 流程对照，但不预设提升百分比。

| 编号 | 任务与测试素材 | 通过条件 | 对应需求 |
|---|---|---|---|
| AT-01 | 整体指标增长，多个目录有增减且存在净零目录 | 从概览进入主要变化目录与文件；可加总量核对一致，净零不隐藏内部变化，均值／比例不错误归因 | FR-04–06、FR-14 |
| AT-02 | 函数增长与同文件同名歧义并存 | 定位可靠函数变化和位置；识别歧义、查看两侧记录及覆盖，不产生全排列 | FR-03、FR-07、FR-12 |
| AT-03 | 文件重复行增长，关联未增长文件，两侧组编号变化 | 找到两侧各自相关组及全部必要片段，取得路径、起始行和长度，不依赖跨版本组号或反算结束行 | FR-08、FR-15、FR-18 |
| AT-04 | 超大目录变化，扫描数量与可恢复成员数量不一致 | 看到直接成员及两种数量，正确理解覆盖差异，不误认完整磁盘目录 | FR-13、FR-16 |
| AT-05 | 阈值／版本差异、未知值、汇总冲突和局部错误 | 识别正常与受限报告，指出受影响结论；未知不被当零，观测差异不被当可靠恶化／改善 | FR-02、FR-04、FR-16 |

### 10.2 正确性最小覆盖

1. 两侧空扫描、有文件无函数、纯注释文件、正常空问题清单，以及缺失／`null`／无效数值的差异。
2. 文件单侧出现、路径移动、多 `-fp` 路径的公共根、相似字符前缀、根外路径、规范化碰撞和两侧根层级变化。
3. 同名函数两侧不同基数、行号整体移动；最大值对象唯一、末尾位置、实际最大值及空集合行为。
4. 四类派生超限清单及目录计数的 `阈值-1`、`=阈值`、`+1`；退出清单后实际数值回补；两侧阈值不同。
5. 分母变化、零分母、百分数尺度、显示舍入、汇总与明细不一致；模拟零分母约定不扩展到未核验真实输入。
6. 重复组编号变化、跨文件／同文件组、零差值但片段变化、重叠覆盖、大组保留、整文件成员去重；L2 与 L3 可证边界分开。
7. 危险函数同名同一行去重、不同名称同一行分别计数、多位置变化；冗余块行号移动；密度特殊规则只用于已定义冗余项。
8. 超大目录直接成员去重、空目录不可见及原始数量与恢复列表不一致。
9. 裁剪前后总量、分母与数量守恒；跨页／跨块搜索排序正确；必要关联和异常不丢失。
10. 中文、长路径／名称、恶意 HTML、重复 JSON 键、非标准数值、损坏数据块、生成中断及交互初始化失败。

具体正负夹具按生成指导 §7 落实，不能用 `sample.json` 作为 L2 一致性正例。

### 10.3 压力与离线测试矩阵

- baseline/current 两侧同时达标，覆盖低变化、中变化、接近及达到 100% 变化。
- 覆盖大量扫描集合进出、大重复组、深宽目录、长路径／函数名和大量同名歧义。
- 每组登记代码行度量、文件／函数／片段数量、两侧重合率、变化比例、保留比例和上下文数量；字符串长度及组规模分布随配置保存，不承诺任意无界分布均达标。
- Chrome / Edge 各自在固定 OS、断网、干净缓存和真实 `file://` 下执行任务；连续导航、重复查询及返回先前目录检查缓存增长和峰值内存。
- 各项门槛逐数据集判定，不能用平均值、单侧满规模或只在低变化比例通过替代全矩阵验收。
