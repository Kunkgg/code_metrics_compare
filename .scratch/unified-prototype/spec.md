# 统一 UI 与容量验证原型

Status: claimed

## 已确认范围

- 基线提交：`da6642ad8fb8147bc13ab8850b235068ffda7e4a`；在 `spike/unified-prototype` 小步迭代。
- `prototypes/ui/` 是功能与交互基线；`prototypes/performance/` 是技术与实验参考。继续使用现有三页 UI，不创建第三套 UI，不提前建立正式产品目录。
- 必须达标：基线／当前每侧 100,000 文件、1,000,000 普通函数、至少 2,500 万非空非注释代码行。200,000 文件／2,000,000 函数用于探索上限，不增加相同硬门槛的承诺。
- 浏览器验收包括 Chrome 和 Edge，必须包含 Windows；尚无指定设备。开发机测量不能替代 Windows 验收。参考条件仍为至少 4 核、16 GiB、SSD。
- 本轮验证仓库已知模拟结构的两份 JSON，包含正常、异常与压力夹具；真实 Cmetrics 版本适配和语义在公司内部 P4 核验。
- 不删除已确认功能，不以 Top N、当前页或已加载块冒充完整查询。先完整保留明细；若实测要求省略独立未变化明细，再验证必要证据、数量和聚合贡献守恒。
- 本轮不修改 `docs/PRD.md` 和 `docs/ARCHITECTURE.md`。所有优化保存相同输入和任务下的前后测量；阶段完成后运行测试并汇报。

## 测量约定

- HTML ≤200 MiB；可操作 ≤10 s；常用交互 P95 ≤1 s；重搜索 P95 ≤3 s；浏览器新增峰值 ≤2 GiB；完整报告生成 ≤10 min／8 GiB。
- 规模、存续修改、集合进出、保留比例分别登记。1%、30%、接近／达到 100% 变化以及大量集合进出独立成组。
- 热查询每任务至少 20 次，nearest-rank 计算 P95；保存每次样本。完整结果检查失败的任务，不计作性能通过。
- 冷查询与热查询分开；干净浏览器启动不等于操作系统磁盘缓存已清空，后者未控制时明确登记。
- 交互覆盖页面请求至 DOM 更新及后续两帧，工具进程启动另计；已有容量 run 接口可作为其历史基线，不代表新 UI 的完整操作。
- 资源采样以独立浏览器空会话为基线，记录完整进程树 RSS 时间序列、增量、进程覆盖及采样间隔。RSS 共享页重复计数、漏采瞬时峰值等局限保留。
- 输入、HTML、源码与 uv.lock 保存 SHA-256；记录 CPU、物理内存、OS、实际浏览器版本、Python／Node／uv／agent-browser 版本、seed 和配置。
- 原始产物写 `output/unified-prototype/`；可版本管理的阶段结论写本目录 issues。原型源码／截图基线由 Git 提交和产物摘要定位，不提交大体积生成物。
