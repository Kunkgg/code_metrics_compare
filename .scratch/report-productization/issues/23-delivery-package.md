# 23: 固定版本交付包与内部验收流程

**What to build:** 内部人员取得可追溯安装包、说明与验证步骤，能够在受控环境复现正式报告和验收。

**Blocked by:** 19：已核验真实 profile 的报告支持；21：正式 P3 变化与分布矩阵；22：正式 P3 长时与真实阅读验收

Status: ready-for-agent

依据：[正式产品化规格](../spec.md)及其中引用的最新 PRD／ARCHITECTURE。沿用 GLOSSARY 术语；本票编号采用用户确认的24票拆分，替代规格中12项里程碑的任务编号引用。

- [ ] 交付固定版本wheel及依赖锁／摘要，整理安装、report参数、元信息、profile、退出码和受限报告说明。
- [ ] 登记实际支持的macOS／Chrome具体组合、参考硬件、已测模式及限制；不声明Windows／Edge或未测试组合支持。
- [ ] 提供直接和传递依赖的许可证清单、离线与安全说明、输入适配依据和已关闭／保留风险。
- [ ] 汇总P1、P2、P3的正式产物及证据索引，分别列正确性、离线、时延和资源结论，所有硬门槛须有适用通过证据。
- [ ] 提供内部P4代表性真实输入选择、业务预期核对、性能测量、结果登记和失败复验流程；材料不要求真实数据外传。
- [ ] P3分支若分别修改了代码，交付候选必须重新验证受影响项，不能组合不同版本的通过证据当作同一发布通过。
