# 04 两组各十项分析指标

Type: prototype
Status: resolved

## 要求

分析入口仍分“常规指标 / 超大指标”两行，每组按用户指定顺序包含 10 项。均值和比例须显示各自的汇总值，不再以总量指标代替。

| 常规指标 | 超大指标 |
|---|---|
| 非空非注释代码行 | 超大头文件 |
| 平均文件代码行 | 超大头文件率 |
| 平均函数代码行 | 超大源文件 |
| 平均函数圈复杂度 | 超大源文件率 |
| 代码重复率 | 超大函数数 |
| 文件重复率 | 超大函数率 |
| 危险函数数 | 超大圈复杂度数 |
| 冗余代码数 | 超大圈复杂度率 |
| 源代码重复率 | 超大目录数 |
| 源文件重复率 | 超大目录率 |

## 实现约束

- 最新名称同步到 `metric_names.md`，所有视图继续使用同一来源。
- 指标选择与明细类型分别保存，共用文件/函数明细的指标也能独立选中、下钻和返回。
- 比例显示百分数，差值显示百分点；均值保留两位小数。
- 源代码和源文件重复率仅列非头文件明细。按现有报告契约，其分母分别为全部有效代码行和全部文件数；不更改生成器公式。
- 比例入口保留重复片段、超限成员及阈值限制等既有证据。
- 保留一次性离线原型边界，在 `prototype/prd-ui-comparison` 分支交付。

## 验证

- 正常数据重建通过两侧现有 L0–L3 校验，JS 语法与 `git diff --check` 通过。
- 浏览器逐一切换 20 个入口，名称、顺序、选中态、明细类型、基线/当前值均与原始报告一致。
- 1512 × 1000 桌面视口两组各占一行；390 × 844 窄屏 20 个按钮全部位于视口内，页面无横向溢出。
- 平均文件代码行显示 `260.63 → 260.96`；代码重复率显示 `1.37% → 2.05%`；超大目录率显示 `15.38% → 15.38%`，变化 `0.00 个百分点`。
- 概览均值卡片下钻保留 `lines_per_file`；全部指标中的 20 项入口均跳转至正确指标。
- 源代码重复率查询 `include/` 无结果；整体代码重复率保留 2 个头文件。源代码重复率选择 parser 当前组 107，跳转 grow 后返回保留源指标与组号。
- 超大目录率进入 bulk，再打开新增成员并返回，恢复目录率入口与 bulk 选择。
- 异常样例下，均值保留汇总不一致提示，代码重复率及源代码重复率保留未知提示，超大圈复杂度率保留阈值变化，超大目录率保留成员不完整提示。
- Enter 键切换平均文件代码行后焦点保持。真实 `file://` 离线运行无外部资源；初始化失败时静态 13 项使用最新名称；正常页面无浏览器错误。
- 独立只读复核未发现确定问题。未新增原型测试套件或生产机制。

## Answer

分析入口按清单完成 10 + 10 项。原先以明细类型选指标的状态已拆为具体指标和明细类型，共用证据时不会丢失均值或比例选择。全报告汇总使用原始报告字段，悬停可查看分子、分母；下方明细保留各对象的代码行、重复标记、复杂度或直接成员数，并明确标出单位。目录合计仅汇总明确标出的明细总量，不把比例相加。

名称统一从 `metric_names.md` 加载，按本轮清单更新 6 处标签。主指标概览仍为 13 项，新增分析入口不扩大概览卡片数量。

- 主来源：`src/cmetrics_cmp_viz/prototype_ui/prototype.js`、`metric_names.md`。
- 构建：`uv run python -m cmetrics_cmp_viz.prototype --open`。
- 入口：`output/prototype/cmetrics-prototype.html`。
- 截图：`output/prototype/analysis-twenty-metrics.png`、`analysis-twenty-metrics-mobile.png`。
- 分支：`prototype/prd-ui-comparison`，不合入 main。
