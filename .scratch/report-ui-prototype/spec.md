# PRD 离线报告 UI 原型对比

## 当前复现入口

目录整理后，在仓库根目录运行 `uv run python -m prototypes.ui.prototype --open`，输出仍为 `output/prototype/cmetrics-prototype.html`；源码位于 `prototypes/ui/`，指标名称位于 `docs/metric_names.md`，定向检查脚本位于 `scripts/prototype_checks/`。下文及各轮记录中的旧命令、源码路径和分支交付说明保留归档分支当时的语境。

## 当前决策

用户已选择 A 概览与 B 三栏分析的组合，C 暂不考虑。当前页面按“概览 / 分析 / 全部指标”组织；分析页按“常规指标 / 超大指标”两组平铺，每组 10 项，桌面端各占一行；均值和比例独立选择，共用对应明细。两侧统一称为“基线 / 当前”，小数显示统一四舍五入到两位。12 项均值/比例合并为“指标变化”：整体变化只展示一次，文件或目录各用一个带正负号的净影响值，按绝对值排序、配正负条形并支持下钻；分子、分母与计算说明默认折叠。原始比较精度和一次性原型范围不变。

以下保留首轮三方案设计与比较背景。

## 要回答的问题

对于质量看护人员与组件接口人，哪种信息组织更适合完成 `docs/PRD.md` 的“发现变化 → 获取定位证据”流程？

首轮比较三个结构不同的页面，不比较不同数据集或不同后端技术。布局选择已见上方“当前决策”，尚未验证正式产品中的效率提升。

## 依据与交付

- 需求基线：[PRD](../../docs/PRD.md)，重点为第 5–8 节、AT-01–AT-05。
- 仓库尚无报告页面或 Web 路由，因此采用新的、明确命名的一次性离线 HTML 原型。
- 三种布局共用一个 `cmetrics-prototype.html`，使用 `?variant=A|B|C` 切换。
- 一键生成数据和报告：`uv run python -m cmetrics_cmp_viz.prototype --open`。
- 原型源码、构建入口和使用说明只归档到 `prototype/prd-ui-comparison` 分支；不合并到 main。
- [实施与手工检查记录](issues/01-ui-comparison.md)。

## 三种候选

| 方案        | 主要结构                      | 适合验证                      | 代价                   |
| --------- | ------------------------- | ------------------------- | -------------------- |
| A · 指标驾驶舱 | 固定侧栏、指标概览、目录贡献、独立分析页与对象抽屉 | 首次阅读能否快速发现变化与可信性限制        | 定位对象需要逐层进入，页面切换较多    |
| B · 分析工作台 | 顶部工具导航、目录树 / 明细表 / 证据三栏   | 能否连续比较多文件、多函数，减少上下文切换     | 首屏信息密度较高，横向空间要求更大    |
| C · 任务式评审 | 五项任务目录、观察提示、证据表和内联详情      | 能否按任务理解证据和不可得结论，尤其适合演示与评审 | 自由探索效率可能低于 B，长页面需要滚动 |

首轮曾建议 A 作为报告入口、B 作为分析工作区、C 作为首次使用引导。用户随后选择 A + B，暂不考虑 C。

## 明确不宣称完成

这不是 P1–P4 验收，也不是完整产品 CLI：不接收任意真实扫描输入，不实现生产级版本适配、路径根漂移处理、Worker/紧凑索引/压缩分块、数据裁剪、压力与资源测试。当前只验证小规模合成数据上的 UI 流程和呈现语义。不会用模拟数据校验通过替代真实口径核验。
