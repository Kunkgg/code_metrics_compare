# 大数据场景原型验证

Status: resolved（验证记录：[issues/01-capacity-validation.md](issues/01-capacity-validation.md)）

分支：`prototype/prd-ui-comparison-large-data`。起点：`1eb1d42`（已认可的小规模 UI 原型）。

## 问题与范围

在基线、当前每侧 10 万文件、100 万函数下，离线单 HTML 能否在预算内完成“发现增长 → 目录下钻 → 文件／函数定位 → 关联证据”？目录很宽、很深时，有限显示与路径检索是否能保留完整可达性？

保留现有 UI 原型作为全部业务呈现的参照。本轮增加专用容量原型，验证紧凑数据、离线 Blob Worker、全范围查询、有限目录／明细／关联片段显示。容量原型不宣称取代现有原型的全部业务交互，也不直接产品化。

## 数据与测量约定

- 固定 seed，先生成明细后汇总；分别保存原始基线／当前扫描 JSON、生成配置与摘要。
- 文件规模按 1,000 → 10,000 → 100,000 放大，每文件 10 个函数。目标矩阵每侧都达到 100,000 文件与 1,000,000 函数。
- 覆盖低（1%）、中（30%）、全量（100%）变化；混合、宽、深目录及长路径、同名函数歧义、大重复组。
- 压力夹具使用确定的紧凑有效行规则，明确与已有逐行 L3 模型的边界；生成器耗时与从两份输入构建 HTML 的耗时分开。
- 实测设备、浏览器与版本入记录；离线使用真实 `file://`，禁用网络并清空浏览器状态。未安装的浏览器／未测试 OS 不宣称通过。
- 浏览器查询计时覆盖发起操作到结果进入 DOM 并完成后续帧，不包含自动化 CLI 启动。冷启动与热查询分开；热任务每项 20 次，P95 使用 nearest-rank。
- 浏览器内存采样独立会话的进程树 RSS 增量，包含 renderer、Worker 等进程；声明 RSS 加总及采样间隔的局限，不用 JS heap 替代完整内存。
- 记录 HTML 体积、打开至交互可用、初始化时间、生成耗时／RSS、浏览器 RSS、查询与目录操作 P95、DOM 数量、网络请求和错误。

## 判断门槛

沿用 PRD §9：HTML ≤200 MiB；概览可操作 ≤10 s；常用目录／分页／筛选排序 P95 ≤1 s；全报告搜索 P95 ≤3 s；浏览器新增峰值内存 ≤2 GiB；报告生成 ≤10 min／≤8 GiB。单项失败如实记录，不能截断数据后宣称原目标通过。

本轮完成条件：产出可复现命令、可阅读 HTML、原始测量记录、核心任务的正确性断言与截图，以及可行性结论／正式实现需要采用的调整／未验证范围。P1 容量证据与完整 P2/P3 验收分别陈述。
