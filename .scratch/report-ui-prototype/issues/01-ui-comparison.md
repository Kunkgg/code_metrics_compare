## 问题

同一组扫描数据采用“指标驾驶舱”“三栏分析工作台”或“五任务引导”时，哪一种更适合发现变化并取得足够的定位证据？

需求来源：用户要求“模拟生成数据，根据 docs/PRD.md 制作原型，提供 2–3 种原型实现进行对比”。参见 [spec](../spec.md)。

## 保留的限制

- 所有小规模明细保留，不实现生产数据裁剪；查询在主线程完整数组上执行，没有 Worker / 紧凑索引 / 分块加载。
- 全报告搜索限定“当前对象类型的全部目录与全部页”；不实现跨类型全文搜索，不读取源码。
- 模拟构建命令不接受任意扫描 JSON，不是产品报告 CLI，不包含真实版本适配及根层级漂移流程。
- 不作 P95、目标规模体积、峰值内存、启动耗时或生成耗时结论。
- 未完成 Edge、其他 OS、真实浏览器双击人工验收及完整安全负例矩阵。
- 前端演示不独立承担生产精度／零分母策略；正式实现需要在生成端预计算并验证全部数值状态。
- 尚无用户方案偏好或已验证的效率提升，不能将“能运行”当作“布局胜出”。

## Answer

当前已经证明：同一组已校验的小规模合成数据可以在一个自包含 HTML 中，采用三个结构不同的交互布局完成代表性定位流程，并显式展示歧义、未知和局部限制。

尚未回答：用户更偏好哪个布局，或是否采用 A 的概览 + B 的分析区 + C 的引导组合。待反馈后记录最终理由，再单独实现正式方案；原型保持在此 throwaway 分支。
