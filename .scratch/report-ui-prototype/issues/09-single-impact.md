# 09 合并变化分析并展示单一影响值

Type: prototype
Status: resolved

## 要回答的问题

用户认为“比例变化与贡献”和“变化贡献”重复、边界模糊，文件贡献的分子／分母／合计三列数字过多。希望从阅读任务出发，快速看懂整体变化，并找出影响最大的文件。

## 本轮设计

- 默认界面只回答两个问题：当前指标较基线变化多少；哪些文件或目录推高、拉低该指标最多。
- 原有三个信息区合成一个“指标变化”面板。左侧突出整体变化，基线与当前值作为上下文；右侧为“文件影响”或“目录影响”。均值／比例页不再在顶部重复展示同一组汇总数字。
- 每个对象只显示一个带正负号的影响值，沿用原“合计”净影响。正值推高、负值拉低，单位保持为行／文件、行／函数、复杂度／函数或百分点。保留原统计和分摊算法。
- 按净影响绝对值排序，配以中心为零的正负条形。条长基于本范围所有对象的最大绝对影响，各页共用标尺，不除以可能为零的整体净变化。
- 分子、分母对比表、平均文件代码行的存续／新增／移出统计及计算说明放入默认折叠的“计算明细”。不再单独呈现分子／分母的整体贡献块。
- 超限指标仍展示新增超限／退出超限，避免整体为零掩盖成员变化。净影响为零但分子分母有变化的对象保留，零值不画条形；悬停数值说明抵消或显示更高精度。
- 无可计算影响时保留原因，整体变化显示“—”，不显示确定排名；零分母的基线／当前值显示“不适用”。
- 延续原型现有单一布局，在 `prototype/prd-ui-comparison` 分支迭代。用户已明确合并与简化方向，不新增候选布局切换器。

## 验证

- `node --check src/cmetrics_cmp_viz/prototype_ui/prototype.js`、`git diff --check` 通过；原型构建成功，正常两侧 L0–L3 校验通过。
- agent-browser 在实际 `file://` 页面分别以 1440px 和 390px 遍历全部 12 项均值／比例。默认仅一个整体变化摘要，文件表为两列、每行一个影响值，计算明细默认折叠且可展开。
- 遍历各指标全部影响分页，以悬停的更高精度数值核对：各对象相加与整体变化误差小于 `1e-6`；绝对值顺序、正负方向、跨页条形标尺一致。
- 即时搜索不改变汇总范围；影响列表第二页下钻精确文件，再返回恢复原指标、查询与页码。函数文件入口和目录入口正常。

- 汇总不一致、重复行未知、超限阈值变化和目录成员不完整对应的五项异常检查通过：显示具体原因，整体变化为“—”，不渲染影响排名。
- 窄屏全部指标及展开计算明细后无页面横向溢出；桌面和移动截图人工查看。浏览器无页面错误，无外部网络资源。
- 独立只读复核未发现必须修复的回归；未新增仓库测试套件。

## Answer

默认阅读路径已收敛为“先看整体变化，再按净影响大小定位文件／目录”。每个对象只有一个影响数字，沿用第五轮定义的合计值，用户不再需要同时理解分子、分母和合计三列。详细统计及公式仍可按需展开。

本轮源码与记录归档于 `prototype/prd-ui-comparison` 分支，不合入 main。

## 上下文

本轮覆盖第五轮中默认展开的三块贡献区域及对象三列呈现方式，数学定义和统计范围保持不变。第五轮记录仍用于追溯原分解公式及异常边界。
