# 17: 离线安全与失败兜底

**What to build:** 正式报告在离线、恶意字符串和运行故障下保留可信内容，并明确告知失败与恢复方式。

**Blocked by:** 05：正式容量机制与 P1 验证；16：跨页分析上下文与查询恢复

Status: ready-for-agent

依据：[正式产品化规格](../spec.md)及其中引用的最新 PRD／ARCHITECTURE。沿用 GLOSSARY 术语；本票编号采用用户确认的24票拆分，替代规格中12项里程碑的任务编号引用。

- [ ] 登记的 macOS／Chrome 真正断网 file:// 阅读，无库、字体、WASM或其他运行外连；输入命令及路径不执行、不访问源码。
- [ ] 路径、名称及诊断中的恶意文本正确转义，检查脚本执行及恶意 DOM；不靠只检查文本内容判定安全。
- [ ] 禁用脚本、初始化失败时仍显示 Python 预生成静态概览，并明确交互不可用；不将静态可读计为交互通过。
- [ ] 损坏块、未知格式、解压错误、Worker 崩溃和运行失败有明确影响范围和恢复路径；旧失败不覆盖当前状态。
- [ ] 通过正式构建产物和故障注入探针验证断网、兜底、重试及完整性检查，保存网络和错误证据。
