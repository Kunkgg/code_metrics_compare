## 已确认的方向

用户确认组合 **A 的概览 + B 的分析区**，C 暂不考虑。这替代首轮 spec 中“尚未选择方案”的状态；首轮代码保留在 `7a5edae`，不再在当前页面维护三个布局。

用户本轮反馈优先于 PRD 旧文案：中文指标名以根 `metric_names.md` 为准；不标“待评审”；超大项只要有可靠新增就突出，不以退出项抵消新增项。未知、匹配歧义和不同阈值仍不得被表述为可靠新增或零新增。

## 检查记录

仍是小规模手工走查，不新增原型自动测试套件，不宣称正式 AT 或容量验收。

- **阈值错误先复现后修复**：直接生成 baseline 后断言 `huge_threshold.huge_folder == 50`。修复前输出 `10 != 50`，修复后通过。原因是原型夹具常量为 10，不是页面把输入 50 解析成 10。
- **真实数据校验**：默认种子两侧通过现有 L0–L3；额外种子 0、1、42 也通过。当前校验器仍只覆盖既定规则，台账结构检查不等于全部台账语义验证。
- **新增不抵消**：浏览器五张超限卡均显示“新增 1”且高亮；逐张点击均进入 `entered` 筛选，各命中一个对应对象。
- **阈值不可比**：异常样例圈复杂度阈值 20 → 25，卡片为“新增 — / 退出 —”，不填零；点击查看全部记录并标不可比较，可靠新增筛选排除这些记录。
- **名称与文案**：13 张卡片名称逐项与内嵌 `metricNames` 一致；可见页面及静态兜底中没有“待评审”、校验层级、旧口号或“合成口径一致”。
- **成员变化**：bulk 的 52 → 52 仍在变化项中；默认显示新增 2、移出 2。全部成员翻页后检索 `nested` 只命中目录；进入后显示 `leaf.c` 200 → 200，返回保留成员查询。
- **关联空结果**：parser → 总重复文件数无命中时仍显示“返回原对象”；返回恢复 parser 与原分析类型。
- **重复组与位置**：两侧独立选组，组 `107` 的定位文本含 `StartLine: 201`、`DuplicationLength: 30`、真实组标识，没有伪造结束行。
- **函数歧义**：`parse`、`func_worker` 各侧两条记录，逐函数变化为“—”，不按行号配对；静态超限进出统计同样排除任一侧同名歧义键。
- **未知值**：异常样例 grow 的重复行为未知，变化为“—”，完整聚合不补零。
- **全量查询**：翻页后输入 `src/utils/shrink.c` 再切“全部目录”，查询词保留，命中 300 → 210 的唯一记录。
- **离线**：Chrome 的 `file://` 加浏览器离线模式，`navigator.onLine=false`，外部资源条目为 0，查询和下钻可用。
- **静态兜底**：禁用脚本后刷新，交互 root 为空，13 行指标可见，5 类新增独立高亮；`?failInit=1` 也保留静态概览。
- **预览开关**：`--production-preview` 隐藏原型状态，不改变数据或冒充生产构建。
- **工程检查**：Node 语法检查、Ruff、格式检查、Pyright、现有 pytest 28 项、`git diff --check` 通过。

浏览器检查使用 agent-browser，主要视口 1512 × 1000；未扩大为 Edge / 跨 OS 兼容验收。未执行生产规模性能测试。
