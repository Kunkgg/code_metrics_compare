## 2. 问题、目标与成功标准

### 2.1 当前问题

1. 结果分散在多个 Excel 中，用户需学习表结构并手工筛选、排序和跨表关联。
2. 重复代码增长只能先定位文件，再查扫描明细和重复组，才能找到相关片段。
3. 超大目录仅有数量，缺少可直接查看的成员与覆盖说明。
4. 文件代码行、重复代码行、函数代码行、圈复杂度缺少目录分层聚合。
5. 文件路径与函数名作为匹配键时，同文件同名函数可能产生多对多全排列，放大或伪造变化。
6. 空值、扫描范围或阈值变化若被当作零值或代码变化，会误导恶化判断。

### 2.2 产品目标

- **G-01 发现变化：**在统一报告中识别看护指标增长及相关目录、文件和函数。
- **G-02 取得定位证据：**将变化与函数位置、重复片段、问题记录或目录成员关联，减少人工跨表拼接。
- **G-03 避免错误结论：**区分可比变化、未知、歧义及扫描记录进出，使证据限制可见。
- **G-04 便于内部交付：**在目标规模下生成可独立分发、断网双击阅读的单 HTML。

产品的任务终点是“取得足够的定位证据”。它不自动判断真实质量根因、责任人或处理结论；用户仍需转到现有 IDE 或代码平台检查源码。

### 2.3 成功标准

- 第 10 节五项业务任务全部正确完成，无需人工跨多个结果表拼接信息。
- 第 9 节离线、安全、容量和性能要求全部通过；不得以静态概览可读替代交互验收。
- 对照现有 Excel 流程记录任务步骤与耗时；当前不设未经测量的效率提升比例或 ROI。
- 原型通过不等于正式交付；公司内部代表性真实数据核验是交付必要条件。

## 3. 用户、使用场景与流程

### 3.1 用户角色

| 角色 | 核心任务 | 产品内任务终点 |
|---|---|---|
| 质量看护人员 | 比较同一代码库两次扫描，发现增长、定位主要变化对象，检查结论可信性 | 得到需评审的指标与相关对象，以及数据质量和可比性说明 |
| 组件接口人／开发人员 | 检查函数变化、重复关系、问题位置和目录成员 | 取得可复制的路径、标识、位置和度量证据，转到现有工具检查 |
| 报告生成者 | 选择两份扫描 JSON，提供可选代码元信息，生成并分发报告 | 得到完整报告或明确失败诊断；不需要管理后台 |

角色可以由同一人承担。报告阅读者不需要 Python，也不需要安装其他软件。

### 3.2 主流程

```text
生成者指定 baseline/current JSON、输出位置及可选元信息
  → 校验、适配、身份匹配、对比及聚合
  → 生成正常报告／受限报告，或失败并提供诊断
  → 阅读者断网双击 HTML
  → 概览确认扫描身份、可比性和指标变化
  → 选择指标，按目录与文件下钻
  → 查看函数、重复组、问题记录或超大目录成员
  → 复制定位信息，在现有 IDE／代码平台继续排查
```

“受限报告”是可明确界定局部异常影响时的有效交付形态，不得伪装成所有分析均成功。正常与受限报告的发布规则见 FR-02、FR-16。

## 4. 首期范围与非目标

### 4.1 必须交付的能力

- Python CLI：一次处理 baseline/current 一组扫描，不以 Excel 为输入契约。
- 单 HTML：资产与运行所需数据全部内嵌；在支持矩阵登记的桌面 Chrome 上真实 `file://` 运行，当前范围为 macOS／Chrome（§9.2）。
- 覆盖第 7 节全部 13 类结果，但不要求对应 13 个页面。
- 概览、目录／明细／证据三栏分析、全部指标；数据质量与报告说明在“全部指标”集中提供，并在受影响位置就地提示。
- 两组各 10 项页面指标、按任务组织的文本与数值筛选、表头排序、有限记录展示及完整范围查询。
- 文件／函数／重复片段等关联定位、可复制定位文本。
- 全部必要变化信息、关联上下文、异常诊断及未变化数据省略说明。
- 预生成的静态概览，以及交互初始化失败时的可读兜底。

### 4.2 首期不做

- 图形化生成器、浏览器上传解析、批量多仓库任务、Excel 输入兼容。
- 本地服务、在线平台、多人协作、账号权限、历史趋势、CI 阻断或质量门禁。
- 自动归因、责任人定位、审批、原因填写、批注或评审备案存储。
- CSV／Excel／PDF 导出、IDE 自动跳转、跨会话保存分析状态。
- 嵌入源码正文、自动读取本地代码库、搜索源码内容。
- 文件重命名／移动追踪、同名函数猜测配对、重复组跨版本身份追踪。
- 正则表达式、SQL、多条件查询编辑器、自定义仪表盘。
- Treemap、关系网络、火焰图；不承诺移动端或未测试浏览器／OS 组合。
- CCA、函数深度、抑制告警等新增看护指标；不得因输入有字段而自动扩展范围。

### 4.3 不得隐性降级的约束

目标规模无法达标时，必须暂停并重新评审。不得静默丢弃必要变化、隐去歧义、仅保留 Top N、以当前页冒充全局查询，或自行改成多文件／服务端交付。修改约束须再次取得需求方确认。

不生成综合质量分数。数量下降但比例上升等情况分别展示，不互相抵消。两项 `warning_suppression_*` 均不分析、不生成、不参与统计一致性校验，也不填为零；输入保留仅为结构兼容（可选解析，不阻塞流程）。

**数值计算与精度基线（G0 固定）：**
- **计算精度与展示精度：**均值、比例、密度使用原始整数比或未舍入数值计算，比较、分类、筛选、排序及聚合不使用显示舍入值。所有对外业务浮点数（含均值、百分率、密度及 `_kloc`、差值和净影响）统一按十进制 Half-Up 四舍五入至两位小数，不能截断；内部保留未舍入分子／分母及精确值用于计算、比较、分类、筛选、排序和聚合，不能用显示舍入值分类。允许显示分项之和与显示总量存在舍入尾差。模拟输入的业务浮点同样按此规则序列化；JSON number 保存数值，界面补齐两位尾零，计数为整数并使用千位分隔。接近零的非零变化不能因显示 `0.00` 归为无变化，可通过原始分子／分母和方向说明核对。
- **零分母与异常值：**模拟输入按合成约定保存 `0`，报告将相应均值／比例显示为 `不适用`，不展示确定差值或净影响排名；原始约定值可在来源信息中核对。真实输入遵守已核验口径，严禁生成 `NaN` 或 `Infinity`。
- **密度指标特殊规则：**`code_size < 1000 → 0` 的特殊规则仅适用于 `redundant_code_kloc`；`unsafe_functions_kloc` 等其他密度指标严格执行除法运算。

### 5.2 值与状态必须分离

| 状态 | 含义 | 对比处理 |
|---|---|---|
| 已观测数值 | 输入提供有效值 | 口径及单位一致时可计算差值 |
| 不在扫描集合 | 完整性与成员证据支持缺项 | 仅对允许零基准的总量按零计算集合进出，并保留缺项来源 |
| 对象存在但无该问题 | 完整问题清单支持无记录 | 对应问题数可为零，不等于文件不存在 |
| 对象存在但未超限 | 未进入超限清单 | 从完整明细回补数值；不可回补时仅显示清单进出 |
| 未知／无效 | 缺失、解析异常、覆盖不明等 | 不填零，不给出受影响数值的确定差值或改善结论 |
| 匹配歧义 | 无可靠一一配对 | 保留两侧记录，不输出确定的逐对象差值 |

- `delta = current - baseline` 仅用于已知、同口径同单位的值，或按上述规则明确赋零的值。
- 正常空容器、缺失字段与 `null` 不等价；函数空集合的表示见第 6.2 节。
- 数据有效性与可比性独立表达。两侧原值可读不等于可作业务判断。
- 已知规则、阈值、版本或范围差异影响的指标标为“不可直接比较”；元信息不足标为“可比性未验证”。可以保留有意义的观测差值，但不得标成可靠恶化／改善结论。仅阈值不同（`threshold-change`）仍比较超大明细：在身份映射、数值和覆盖可靠时，按各侧阈值严格 `>` 判定，展示可确定的新增／退出超限、两侧数值及有意义的观测差值，明确提示“阈值变化，清单进出和数值变化不证明代码恶化或改善”。版本、映射、未知、歧义与覆盖限制继续适用；详情放开不等于净影响分解放开，阈值不可比等情形仍不输出确定净影响或排名。
- 比例显示两侧百分数及百分点差值；首期不以相对增长率代替绝对差值。显示舍入不得改变判定精度，小幅增长显示近零时须能查看未舍入分子／分母并解释标记，对外业务浮点仍统一显示两位。
- 危险函数、冗余代码等位置记录统一称“扫描记录新增／消失”，不称已证实的“问题新增／修复”。文件路径进出也不证明磁盘文件真实新增／删除。

### 5.3 聚合与统计规则

- 常规目录聚合覆盖后代文件；超大目录直接子项计数不递归，两种口径分别命名。
- 可加总量按两侧分别聚合再求差值，保留有效对象数、增长／减少及歧义数量；目录净零不能掩盖内部变化。
- 平均值、比例根据对应总量和分母重算，不平均已有平均值，不相加比例。平均值和比例变化不能直接分摊为各子项差值的简单和。
- 文件代码行与重复代码行分别使用 `file_sizes[path][0]`、`[2]`；重复组片段长度之和不能替代文件重复行数。
- 全局扫描汇总原值与明细派生值分别标识。若不一致，展示冲突及影响，不强制对齐，不静默择一作为已验证事实。
- 缺项或未知导致的部分聚合须标明覆盖范围，不冒充完整总量。裁剪后的剩余列表不能用来重算原始总体均值。
- 公式与分母参考生成指导 §4；其中百分数尺度、零分母及其他合成约定对真实输入的适用性仍须核验。

### 5.4 均值／比例的指标变化与净影响

覆盖 3 项均值、4 项重复率及 5 项超大率，共 12 项。已确认的呈现如下：

- 默认解释全报告；选择目录后解释该目录及其后代。明细文本搜索、变化类别、数值条件、排序和分页不改变解释范围，面板须显示实际范围。
- 只展示一个“指标变化”面板：整体差值一次，基线／当前作为上下文；每个文件或目录只展示一个带正负号的净影响。正值推高、负值拉低，使用对应均值单位或百分点。
- 净影响按绝对值排序，正负条形以本范围全部对象的最大绝对影响为共同标尺，各页一致；不除以可能为零的整体差值。保留正负抵消及净影响为零但分子／分母有变化的对象，零值不绘制条形。
- 分子／分母对比与计算说明放入默认折叠的“计算明细”。平均文件代码行补充存续、新增、移出文件的数量与代码行；超大率保留独立的新增／退出超限。
- 函数类指标按文件汇总两侧原始函数值，超大目录率按目录解释。分母贡献也须可达，例如源代码重复率可受头文件代码行变化影响。
- 全报告原始汇总先与明细核对，目录按完整明细重算；目录分母包含选中目录本身及其可见后代，全报告包含根目录。未知、零分母、汇总冲突、阈值不可比或覆盖不足时保留原因，不给出确定净影响或排名。
- 点击影响项精确下钻到该文件／目录，返回恢复指标、范围、查询及影响页。计算前后的完整范围不得被显示分页或裁剪后的明细替代。

**正式分摊口径（§13.3 D-03 已确认）：**先在基线分母下替换分子，再按当前分子调整分母。设范围分子为 `N₀、N₁`，分母为 `D₀、D₁`，对象 i 的分子变化为 `Δnᵢ`、分母变化为 `Δdᵢ`，均值 `k=1`、比例 `k=100`：

```text
对象净影响ᵢ = k × [Δnᵢ / D₀ − N₁ × Δdᵢ / (D₀ × D₁)]
全部对象净影响之和 = k × (N₁ / D₁ − N₀ / D₀)
```

只在两侧分母有效且非零、分子分母可按对象完整分配时计算。改变分解顺序可能改变对象数值和排名，虽然总差值不变；净影响是算术解释，不是根因或撤销对象后的效果。按原始精度核对守恒，逐项显示舍入后相加可以有尾差。

## 6. 输入、身份与可信性边界

### 6.1 输入与兼容范围

- 输入为同一代码库的 baseline/current 两次全量扫描 JSON，包含 `summary_metrics` 和 `detail_metrics`；不是只扫描改动文件的增量结果。
- 首期范围为 C/C++（`clike`）和已定义的 POSIX 路径形式。真实支持版本及差异须在内部核验后登记；不宣称覆盖全部 Cmetrics 版本。
- 支持恰一个 `-fp` 参数，其值为一个或多个逗号分隔的绝对扫描目录，并包含 `-l clike`。命令仅解析和展示，永不执行。
- 首期不支持相对路径、引号包裹、路径本身含逗号、控制字符、多个 `-fp`、`.`／`..` 段、重复斜杠、符号链接解析或 Windows 风格扫描路径；超出范围显式报错，不猜测、不依赖源码文件系统。
- 每侧从扫描路径集合按路径段计算公共根，再得到仓库相对路径。不得按字符公共前缀截断或盲目转小写。
- 明细须位于声明扫描范围内。路径规范化碰撞、根外路径、无可用公共根及两侧根层级改变导致的映射问题必须显式诊断；不能静默解释为大批新增／删除。
- **扫描根路径层级漂移处置：**若 baseline 与 current 提取的公共根目录层级不一致（导致相对路径命名空间不对齐），报告生成器应判定为局部阻断（FR-02），发布受限报告：
  1. 概览区与顶部全局 Banner 明确提示：`扫描根路径不一致，文件级对比已降级`；
  2. 停止计算文件级与函数级的跨版本差值，仅展示各侧自身聚合总量；
  3. 禁止将路径结构平移静默识别为 100% 文件删除与 100% 文件新增。
- 扫描输入的路径语法与报告阅读平台分别定义；Windows 阅读未纳入当前验收范围，浏览器／OS 支持见 §9.2。
- 原始键、历史输出表名及拼写差异必须通过显式适配映射处理，不自动将近似拼写认作同义。模拟 Schema 的严格未知字段规则不直接充当所有真实版本的兼容策略。

### 6.2 关键字段与实体身份

| 对象／字段 | 必须遵循的规则 |
|---|---|
| 文件 | 使用规范化的仓库相对路径匹配；不追踪移动／重命名 |
| 函数 | 经验证的稳定身份可用于匹配；只有路径和函数名时，键在两侧均唯一才配对。任一侧同名冲突均隔离为歧义，不按行号强配，不生成笛卡尔积 |
| `file_sizes` | 三元数组依次为非空非注释代码行、物理总行、文件有效重复行；不得调换或用片段长度替代第三项 |
| `method_metrics` | 唯一最大值对象必须位于末尾，包含 `maximum_cyclomatic_complexity`、`maximum_nbnc_loc`，且值与普通函数一致；不得计为函数 |
| 无函数 | 数组仅含上述最大值对象，两项均为 0，不是空数组；不由此推断其他零分母行为 |
| `file_duplication` | 完整文件内容 MD5 一致的文件分组；不按名称或后缀判定。输入缺少内容／MD5 时不宣称已独立验证内容相同 |
| 重复组 | 组身份限定于所属扫描；两侧相同编号不等于同一组 |
| 重复片段 | 使用路径、`start_line`、长度 `code_duplication` 定位；不依赖可选 `end_line`，不由长度反算物理结束行 |
| 危险函数 | 粒度为 `(文件, 危险函数名, 行号)`；同文件同名同一行去重，不同名称同一行分别计数 |
| 冗余代码 | 数组条目为代码块起始行；数量单位是块，不是代码行；不擅自套用危险函数的去重规则 |
| 超限对象 | 文件代码行、函数代码行和圈复杂度按各侧生效阈值严格 `>` 派生，不要求扫描器额外输出四类超限清单 |
| 超大目录 | 输入给出直接子项数，成员从完整文件集合恢复；只承诺扫描可见成员，不承诺磁盘完整目录 |

同名函数无法配对时，按同文件同名称分别汇总两侧有效原始值，展示集合总量及差值，并明确标注“同名函数可能混淆”、两侧记录数和原始定位证据。该数值是集合变化，不是确定的逐函数变化；任一成员值未知时保留未知及覆盖，不补零。逐函数解释须显示匹配覆盖率，不能用歧义配对结果解释整体差值。

### 6.3 代码元信息与可追溯性

baseline/current 分别允许手工提供仓库、分支、节点、版本号，全部可选。“节点”为 commit ID 或 revision，与可读版本号分开。未填显示“未提供”，不从文件名推断；来源标为“用户提供、未验证”。

扫描工具版本来自 `cmetrics_version`，不是代码版本。代码版本不同不构成不可比理由；可比性检查针对工具版本、各项阈值、语言、扫描范围及可获得的规则。不同检出根导致命令字符串不同，不应仅按文本不等判断不可比；文件集合变化本身也不是扫描范围定义不一致。

报告须记录生成器版本、报告数据格式版本、输入摘要标识、各侧扫描元信息、有效／异常记录数量、匹配覆盖及保留／省略范围。输入摘要用于追溯，不证明输入来源可信。

### 6.4 校验分层与不能证明的事实

沿用生成指导的 L0–L3：L0 检查 JSON 与重复键／非标准数值；L1 检查结构；L2 检查末尾对象、引用、命令、公式及阈值等语义；L3 仅检查生成器内部有效行、重复覆盖及变化台账。

模拟生成器的正常输出须通过相应分层校验；错误夹具必须单独标记。真实输入采用经核验的版本适配与语义规则，不能因模拟 profile 校验通过就宣称真实口径已验证。

仅凭片段起点与有效长度通常无法重建有效重复行并集。外部输入只能复核文件重复量与汇总等可证关系，不能宣称已验证真实重复覆盖。其他尚未核验事实见第 12 节。

## 7. 功能需求与结果覆盖

以下 FR 均属于首期必须需求，除非条目明确说明条件；实现顺序不改变正式交付范围。

### FR-01 报告生成

使用者通过 Python CLI 指定两份 JSON、输出位置及可选两侧元信息，一次生成一个 HTML。输入中 baseline/current 身份必须显式指定，不由文件名猜测。生成过程提供阶段／执行状态及失败原因。

最终产物必须在必要校验完成后发布；生成中断或失败不得留下被误认为成功报告的半成品。参数名称、安装方式和内部数据格式在技术设计中确定，不在 PRD 中冻结。

**验收：**同一组输入可重复生成语义一致的结果；交换两侧后，有效同口径数值的差值方向正确反转；报告阅读不依赖输入 JSON 仍在原位置。

### FR-02 分级校验与处理结果

- 全局阻断：无法解析、顶层核心结构损坏或无法建立可靠全局路径映射时，不发布正常对比报告，提供可定位的诊断。
- 局部阻断：可界定影响范围时停止相关处理，保留其他可靠结果并发布受限报告；不能隔离的错误须提升为全局阻断。
- 局部未知／歧义：不得补零、任选配对或隐去；受影响模块明确不可得的结论。
- 正常空结果：显示“无变化／无记录”等符合实际范围的状态，与异常空白区分。

**受限报告 UI 规范：**
- **全局警示 Banner：**固定在页面顶端醒目位置，黄色（局部阻断／警告）或红色（严重限制），写明受限原因（如：`圈复杂度函数匹配存在歧义，部分逐函数差值已屏蔽`）及受影响的模块范围。
- **受影响模块标记：**受影响的下钻入口保留但附带 `[受限]` 标签，点击进入后首先展示限制说明面板与各侧原始数据，不展示未经证实的确定性差值。

**验收：**错误包含扫描侧、字段或对象、原因及影响范围；第 5.2 节状态可区分。未知值须传播到受影响的范围合计、祖先目录和关联证据；未知、歧义、阈值变化等原因可并存，不得互相覆盖。概览、分析、全部指标和静态兜底使用一致的受限原因，不依赖演示场景开关。

### FR-03 可信匹配与比较

按第 6 节建立文件、函数及位置记录的身份；合并前检查键基数，先校验、匹配、聚合和关联，再裁剪数据。各类差值遵守第 5 节规则。

**验收：**同名函数不产生笛卡尔积；根层级变化不被静默误识别为文件变化；行号移动可产生位置记录进出，但不会自动标为问题真实新增／修复。

### FR-04 概览

提供 §5.1 两组各 10 项指标卡片、两侧代码与扫描身份、可比性以及关键数据质量提示。卡片突出差值，辅以基线、当前和单位；点击进入对应指标分析，数据不可用时先说明原因。

- 提供可组合的“增长 / 新增”“减少 / 退出”“无变化”，默认选前两项；允许全部取消并显示正常空状态。页内导航保留选择，刷新恢复默认。
- 常规指标按汇总原始差值分类。超大指标同时考虑净变化和超限进出：新增／退出各 1、总数不变时，仍出现在相关变化类别；只有差值为零且无进出才属于无变化。
- 超大卡片分别展示新增超限、退出超限数量；点击卡片进入该指标，点击进出数量进入对应明细。数量与比例入口使用同一类超限对象。
- 目录代码行变化图与文件增长／减少列表随概览方向选择联动；截取展示需提供完整范围入口。异常保留醒目提示，不强行归入增长、减少或无变化。

**验收：**20 项页面指标、13 项过程汇总及必要明细最大值覆盖完整；三页名称、分组、顺序一致；微小变化、净零但有进出、无选择及异常均正确呈现。来源与可比性可查，缺项不补造，抑制告警不进入分析，不出现综合质量分数。

### FR-05 目录分析与基础图表

提供目录树、路径上下文及层级下钻。文件代码行、重复代码行、函数代码行、圈复杂度均支持目录聚合，展示两侧总量、差值和有效对象数量；涉及均值／比例时展示相应分母和口径。

以指标概览、目录导航和可排序表格为主，提供可加总量的增长／减少条形图，以及按 §5.4 定义的均值／比例净影响图。图表可有限展示，但必须说明指标、范围、排序及数量，并可翻页或进入完整保留记录。目录净零但内部有变化时仍可下钻。

目录很宽或很深时，按层级有限展示，保留路径上下文、返回上级及路径检索；用户必须能找到未在当前页显示的目录。分页、按需展开或虚拟显示不改变底层查询范围，不要求一次将整棵树放入页面。

**验收：**父目录在完整可加总集合上与后代贡献一致；未变化记录的聚合贡献未丢失；超大目录直接子项不混作递归总量；均值和比例遵守 §5.4，不能把子项自身均值／比例差简单相加。

### FR-06 文件分析

显示文件相对路径、各侧存在性、非空非注释代码行与重复行的原值及变化；同一文件可进入函数、重复组、危险函数和冗余代码等关联明细。路径进出使用扫描集合语义。

**验收：**无重复问题与文件不在扫描集合可区分；文件其他度量或关联结构发生变化时，不因当前单一度量差值为零而被删除。

### FR-07 函数分析

在目录／文件范围内查看函数代码行与圈复杂度，可展示两侧函数名、位置、原值、差值、超限状态及匹配状态。普通函数起止行用于定位，不作为未经验证的跨扫描稳定身份。

**验收：**唯一键变化可定位；同名歧义可查看两侧原始记录及原因；最大值对象不出现在函数列表或函数计数中；聚合与逐函数解释覆盖分开说明。

### FR-08 重复代码联查

从文件重复行变化进入 baseline/current 各自的重复组，再查看组内所有相关片段的文件、起始行及长度。允许查看未增长文件中的必要关联片段；不按跨扫描组编号相同建立身份对应。

**验收：**重复增长文件可沿报告内关联找到其他相关片段，无需人工跨表检索；裁剪不切断组关系；片段数值和定位不依赖反算结束行；重复量以文件字段为准。两侧独立选组，组列表、片段与关联文件分别在完整集合内搜索和分页；精确下钻后返回恢复两侧选组及各集合条件、页码。由源重复指标关联到头文件时，切换到对应完整指标查看，返回恢复入口上下文。

### FR-09 重复文件分析

显示文件进入／退出重复文件记录集合及两侧组成员上下文。统计按成员路径并集，不将组数或组内重复出现次数当作重复文件数。

**验收：**文件在多个组中不重复计数；无重复记录和不在文件集合可区分；两侧编号变化不被解释为稳定组身份变化。

### FR-10 危险函数分析

按文件、危险函数名、行号展示位置记录及进出。汇总为各文件、各名称下去重行号数组长度之和；同一行不同危险函数分别保留。

**验收：**一个位置不被还原为同一行的多次调用；同名多位置变化不被文件级或名称级匹配吞掉；定位文本说明这是去重位置记录。

### FR-11 冗余代码分析

按文件与代码块起始行展示记录及进出，提供定位信息。数量表示块数，不表示冗余代码行数。

**验收：**起始行移动不被描述为已证实的问题修复／新增；同文件、同起始行的条目重数保留，不擅自去重或合并为一块。

### FR-12 四类文件／函数超限分析

从完整文件／函数明细和各侧阈值派生超大头文件、超大源文件、超大函数、超大圈复杂度函数。展示清单进入／退出、可取得的两侧数值及阈值。

**验收：**等于阈值不超限，严格大于才超限；退出清单仍显示可回补的实际值，不补零；两侧阈值不同仍按各侧阈值展示可确定的清单进出和有意义的观测差值，提示变化不证明代码恶化或改善；函数歧义规则同 FR-07，净影响限制同 §5.4。

### FR-13 超大目录分析

展示两侧扫描提供的直接子项数，以及由文件路径恢复的直接文件、直接子目录列表。直接子目录去重，不递归将后代文件列为直接成员。

**验收：**扫描数量与可恢复成员数分开展示，差异及覆盖限制明确；不补磁盘空目录，不宣称拥有完整本地目录；必要成员名称与类型不因度量未变化而被裁剪。阈值不同仍遵守 §5.2：按各侧阈值严格 `>` 展示可确定的进出及观测差值，提示变化不证明代码恶化或改善；覆盖、映射与未知限制保留，净影响继续受 §5.4 限制。

### FR-14 统一搜索、筛选与排序

- 变化类别按当前查看的度量或记录类型定义。普通数值列表提供“全部变化 / 只看增长 / 只看减少 / 无变化 / 全部对象”；超限列表使用新增／退出超限，记录列表使用扫描记录新增／消失或进入／退出重复清单。
- 当前数值相同统一显示“无变化”；仅位置、其他度量或关联关系改变的对象不进入该数值列表的“全部变化”，但必要原始记录及关联证据仍保留可查。默认查看当前指标的变化及异常，不将未知或歧义归为无变化。
- 点击目录限定当前目录及后代；切回全部目录后搜索覆盖当前指标全报告的保留记录。路径或名称输入后即时查找；不要求跨指标、跨对象类型混合返回结果，也不搜索源码。可检索标识包括适用的文件相对路径、函数名、危险函数名和超大目录路径。
- 数值条件为可选展开项，使用基线值、当前值、增加量或减少量，配“至少 / 不超过 / 介于”和实际单位；增加量、减少量均输入非负数，区间包含边界。应用数值条件时切到“全部对象”，避免叠加隐藏的旧类别。
- 点击表头切换排序，显示当前方向；筛选、搜索和排序先作用于完整声明范围，再分页，结果数量以完整命中计数。相同值使用稳定决胜顺序；路径升序的函数列表先按文件路径、同路径再按函数名排序，不因翻页或重查漂移。大数据不得只查当前页或已渲染对象。
- 当前范围、查询词、变化类别、数值条件、排序及命中数量持续可见，条件可单独移除。切换指标时清除不适用条件和旧对象选择；精确文件下钻后返回，应恢复入口指标、目录、查询、排序和页码。
- 异常有独立入口；主动筛选排除异常时，仍提示本范围存在异常。无对象、无变化、条件无匹配与查询失败分别呈现。
- 长操作显示执行反馈；首次部分结果不冒充最终结果；发生新查询时，旧成功或旧失败响应均不得覆盖当前查询、视图或对象状态。查询失败时保留上次成功结果并明确标注其状态，允许按最新条件重试，不能把旧结果冒充新查询结果。列表、目录、影响排名和全部关联证据集合均有限显示，并保留完整可达性。
- “全部对象”和“无变化”的查询范围均限于声明范围内已**保留**的明细，不承诺所有原始未变化明细均可查询（§13.3 D-02）。省略范围和数量可查，不能把未保留数据称为无匹配，也不能把保留对象数当作原始对象总数。

**验收：**跨页／跨块命中、排序和数量与全范围预期一致；仅其他度量变化的对象在当前指标中为无变化，异常始终可达；清除条件、切换指标及往返下钻无隐藏旧条件；数值条件含单位且减少量方向正确。

### FR-15 定位信息复制

支持复制路径及简短定位文本。文件／目录只复制相对路径；具体位置复制中文扫描侧别、路径、行号及必要名称。度量、状态、组号和片段长度在证据区查看，不默认塞进复制文本。

- 文件／目录：`src/core/parser.c`、`src/core`。
- 函数：`当前：src/core/parser.c:120（parse_token）`。
- 重复片段：`基线：src/util/helper.c:45`；片段有效长度仍在详情明确显示，不反算结束行。
- 危险函数位置：`当前：src/net/socket.c:88（strcpy）`。
- 冗余块：`当前：src/ui/view.c:210`。
- 匹配歧义时保留中文“同名无法配对”提示；缺少行号或名称时仅复制实际可取得信息，不伪造位置。

**验收：**基线／当前不会混淆；点击具体关联片段后复制该片段的位置；不能自动复制时可手动选择完整文本。不触发 IDE、不读取源码、不执行输入命令，报告仍是完整分发载体。

### FR-16 数据质量与报告说明

在“全部指标”内提供集中说明区，列出输入身份、校验结果、可比性、匹配覆盖、记录数量、保留／省略范围和已知限制。技术来源、字段名和输入摘要默认折叠；面向阅读者使用可理解的影响说明，不将 L0–L3 等工程层级作为日常操作内容。严重问题同时出现在概览及受影响结果旁，不能只藏在折叠区。

**验收：**用户能判断报告是正常还是受限、哪些结论不可得、哪些数据未保留；不能从某个“校验通过”推导成 L0–L3 或所有真实语义均通过。

### FR-17 离线阅读与静态兜底

报告通过真实 `file://` 打开，所有交互资产和数据均自包含。JavaScript 被禁用时，至少能读取预生成的 20 项指标静态概览、可确定的超限进出、扫描身份及关键数据质量提示，并知晓交互不可用；初始化失败须显示错误及不可用功能，不长期停在伪加载完成状态。静态概览与交互页共用指标名称、分组和格式。

**验收：**无网络、干净缓存下交互正常；禁用脚本或模拟初始化失败时静态内容仍可读；空白明细不会被表示为无变化。脚本可运行但 Worker 初始化失败时提供明确错误和重试入口，成功恢复后才表示交互就绪；运行期间失败遵守 FR-14 的旧结果保留和重试规则。只有交互正常加载后才表示支持搜索、筛选和下钻。

### FR-18 必要数据保留与省略透明化

先完成校验、匹配、聚合及关联，再省略真正不需展示的未变化明细。保留全部必要变化、异常、关联上下文及导航信息，并保留被省略对象的数量和聚合贡献。

**数据保留边界：**
- **必要数据：**所有指标的数值变化、状态异常与歧义、目录聚合贡献、全局汇总、必要结构／位置证据与导航信息，均不得丢失。
- **关联上下文：**变化文件所属重复组的全部必要片段、超大目录扫描可见直接成员及跨对象定位关系，须完整可达；显示分页不等于裁剪。
- **可省略数据：**仅限在校验、匹配和关联完成后，确认对全部指标与必要证据均无影响的独立未变化明细。省略后的数量、聚合贡献与不可检索范围必须声明；本期不增加全部原始未变化明细可查的承诺（§13.3 D-02）。
- **容量保护：**先采用紧凑表示、压缩和有限渲染；接近 200 MiB 时不得把必要位置／结构证据降为可删除数据。允许省略的独立未变化数据仍不足以达标时，按 §4.3 暂停评审。

“无变化”是当前指标的显示分类，不是可删除判据。必要重复组成员、超大目录成员、其他度量变化、结构／位置变化与歧义记录，均不可仅因当前差值为零而删除；它们可以不进入当前数值列表的“全部变化”，但仍应能在相应对象、记录或关联详情中查到。仅有总量而无法识别结构变化时，不宣称对象完全未变。

**验收：**裁剪前后汇总和有效对象计数守恒，必要关联可达；报告明确省略范围；未保留明细不可展开或检索的限制准确可见；不得为体积达标静默截断必要数据。

**当前原型证据：**统一原型未省略原始明细，完整查询在 Worker 内完成，页面仅取得当前页及必要汇总。该结果支持先保留全部明细的实现起点；D-02 的可省略边界仍保留，但若正式实现启用省略，须另验守恒、必要证据和范围说明，不能直接继承本轮完整保留模式的结论。

### 8.1 已选页面与交互基线

以 [当前 HTML](../output/prototype/cmetrics-prototype.html) 为视觉参照，采用浅色背景、卡片／表格内容区和顶部“概览 / 分析 / 全部指标”导航。保持当前信息密度、分组与阅读顺序；不冻结像素尺寸、前端框架或组件实现。A 概览与 B 三栏分析已合并，不保留 A/B/C 方案切换或 C 任务式页面。

1. **概览：**展示扫描身份、关键限制、两组各 10 项指标、方向组合切换，以及目录代码行图和文件增长／减少列表。卡片和超限进出分别提供精确下钻入口。
2. **分析：**顶部常规／超大两行指标入口；下方为左侧目录、中间明细、右侧证据。12 项均值／比例另有一个“指标变化”面板，突出整体差值及对象净影响，计算过程折叠。关联片段与目录成员使用加宽详情，避免长路径、两侧记录和成员列表挤在窄栏。
3. **全部指标：**同样的两组各 10 项，五类超大指标每类数量与比例共用一条带单位的阈值条件；两侧阈值不同时并列显示基线／当前条件，条件未知时显式说明。新增／退出计数可下钻；14 项计算过程数据及技术来源默认折叠，数据质量说明在此集中提供。

全界面两侧统一称“基线 / 当前”。当前指标、目录、条件、数量、单位、阈值与异常入口可见；常规操作说明和重复口径段落不常驻，计算细节按需展开。错误、限制及导致结论不可得的原因必须就地显示。状态使用文字、符号和颜色共同表达，不能仅靠颜色。

大数据下保持上述任务路径，对目录、明细、影响排名和关联证据有限渲染；当前页之外的对象仍可搜索、排序、翻页和定位。每页数量和具体目录控件不以容量原型的演示常量冻结。

模拟场景切换、种子、原型状态 JSON、压力测试按钮和基准日志属于开发／验证工具，不进入正式报告的常规阅读流程。状态仅在当前阅读会话保留，刷新恢复默认，不新增跨会话存储。

统一原型已在同一三页 UI 下验证紧凑数据、压缩分块、Blob Worker、完整范围查询及有界分页；这些是方案深化的已有证据，不表示正式架构已全部冻结。列式查询、Arquero、DuckDB-Wasm 等未因原型存在而自动入选。产品要求是离线、完整范围查询、有限渲染和资源门槛；最终格式、索引及依赖在技术设计中说明。许可证与依赖仍须按实际选定版本审查。

## 9. 非功能需求与性能门槛

### 9.1 规模与性能（NFR-01）

必须达标的目标规模为 baseline/current **每侧**至少 2,500 万非空非注释代码行、10 万文件、100 万普通函数。两侧必须同时达到文件／函数规模；重复组、位置记录、长字符串和上下文分布也须纳入测试，不以行数单独保证容量。每侧 20 万文件／200 万函数仅用于探索上限，不增加相同硬门槛的承诺，也不作为当前原型收口条件。

| 项目 | 验收门槛 |
|---|---|
| 参考设备 | 4 核或以上 CPU、16 GiB 内存、SSD |
| 浏览器 | 支持矩阵登记的 macOS／桌面 Chrome，固定实际版本；Windows Chrome／Edge 与 macOS Edge 不纳入当前验收要求 |
| 最终单 HTML 体积 | ≤ 200 MiB，含静态概览、资产、数据和索引 |
| 打开至概览可操作 | ≤ 10 秒；仅静态内容出现不算可操作 |
| 常用目录下钻、分页、已有索引的筛选排序 | P95 ≤ 1 秒 |
| 跨全报告搜索等较重操作 | P95 ≤ 3 秒，执行期间有反馈 |
| 报告新增的浏览器峰值内存 | ≤ 2 GiB，包含页面、Worker 及实际使用的 WASM 等相关开销 |
| Python 报告生成耗时 | ≤ 10 分钟，从读取两份输入至最终 HTML 写完 |
| Python 报告生成峰值内存 | ≤ 8 GiB |

MiB／GiB 使用二进制单位。历史“5 万文件约 150 MB”只是用户容量参考，不是线性预测或产物预算依据。模拟生成器的预演目标另见生成指导，不得用数据生成耗时或内存冒充报告生成验收。

**测量要求：**记录 CPU、物理内存、OS、实际浏览器与依赖版本、数据种子、配置、任务集及输入／HTML／源码／锁文件摘要。冷／热查询分别记录，每任务至少 20 次，以 nearest-rank 计算 P95，并保存逐次样本；不足 20 次不输出验收 P95。计时包含实际页面请求、DOM 更新及后续两帧，不能把重选当前指标而未发起查询的点击计入性能结果。完整结果正确性未核对的任务不计性能通过。

浏览器内存以独立干净空会话为基线，记录完整进程树 RSS 时间序列、增量、采样间隔、进程覆盖及读取错误，不能只用 JS heap 代替完整开销；同时记录概览可操作与数据初始化完成时间。干净 profile 不等于清空 OS 磁盘缓存，首次任务也可能复用前序任务索引，均须明确登记。自动化通道失败与页面失败分开归档；确认属于通道断连时，丢弃该次会话样本并用新会话补足，长时运行须整段重跑，不拼接失败片段。报告生成计时包含必要校验，单独打包耗时不得替代完整管线。

- 测量中出现过 oracle 字符串上限、DevTools 通道 IO reset 和证据驱动启动竞态；分别经流式扫描、会话级丢弃重试和结构化就绪等待修复。失败与重跑分别归档，不混合样本或将工具失败冒称页面通过。故障专项还记录了一次重跑覆盖中间证据的流程失误，保留该追溯限制。
- 原始输出位于 `output/unified-prototype/`，由上述 issue 定位输入、HTML、源码摘要及逐次样本；本机原型收口允许带上述限制，不等于免除正式交付门槛或 P4 内部真实核验。

### 9.3 安全与保密（NFR-03）

- 开发以合成数据为主，真实核验在公司受控环境完成；不要求上传公司材料。
- 路径、函数名、指标名称、分支、版本、命令和错误文本均按不可信文本处理，不得注入可执行 HTML／脚本；覆盖 `</script>`、特殊字符及模板注入测试。检查须同时确认未执行、未生成恶意 DOM 节点且原始文本可读，不能仅以 CSP 阻止执行判定通过。
- 扫描命令禁止执行，输入路径不得触发源码读取或任意文件访问。
- 报告仍可能包含敏感路径、标识和度量，沿用公司存储与分发规范；单文件不提供访问控制、撤销或保密保证。
- 固定并登记第三方依赖版本及许可证，检查最终产物无外连；浏览器或内嵌依赖升级后回归真实 `file://` 路径。

### 9.4 正确性、可恢复性与可理解性（NFR-04）

- 输入错误、局部受限和正常无结果的呈现遵守 FR-02，不发布看似完整的缺项结论。
- 长操作显示执行状态，查询结果范围与数量可核对；不能用加载动画掩盖无限等待或失败。
- 中文为主要界面语言，字段标识和代码名称保持原文；单位、侧别、状态采用文字说明，不依赖用户记忆颜色。
- 报告为静态快照，修正输入、元信息或对比逻辑后重新生成；不回写输入或保存跨会话状态。
