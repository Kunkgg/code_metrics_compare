# Cmetrics 离线对比报告正式产品化

Status: ready-for-agent

## Problem Statement

质量看护人员和开发人员需要比较同一代码库两次扫描，识别指标变化并取得定位证据，同时区分真实可比变化、扫描集合进出、未知及匹配歧义。

现有统一原型已验证主要业务交互和部分目标规模场景，但正式报告 CLI、正式计算管线、安装包与完整验收尚未完成。原型结论不能代替正式产品及真实输入验收。

## Solution

提供 Python CLI，读取基线与当前扫描 JSON，生成自包含的离线单 HTML。阅读者通过概览、三栏分析及全部指标完成变化发现、目录下钻、证据查看与定位信息复制。

沿用已确认架构，依次完成正式 P1 纵向链路、P2 全业务、P3 完整验收和 P4 内部真实数据终验。开发开始时并行启动真实输入契约核验。

## User Stories

1. As a 报告生成者, I want 指定基线、当前和输出位置, so that 我能生成一次扫描对比报告。
2. As a 报告生成者, I want 提供可选代码元信息, so that 阅读者能识别比较对象。
3. As a 报告生成者, I want 明确区分正常、受限和失败结果, so that 我能判断报告是否可分发。
4. As a 报告生成者, I want 中断或失败时保留既有报告, so that 有效产物不会被半成品替换。
5. As a 阅读者, I want 只接收一个 HTML, so that 我能断网双击阅读而无需安装 Python。
6. As a 质量看护人员, I want 查看扫描身份和可比性, so that 我能判断结论适用范围。
7. As a 质量看护人员, I want 浏览两组共 20 项指标, so that 我能选择需要分析的变化。
8. As a 质量看护人员, I want 分别查看新增超限和退出超限, so that 总量不变不会掩盖清单变化。
9. As a 质量看护人员, I want 查看计算过程数据及两侧原值, so that 我能核对指标结果。
10. As a 质量看护人员, I want 按目录下钻, so that 我能定位变化集中的范围。
11. As a 质量看护人员, I want 对完整声明范围筛选和排序, so that 当前页不会限制分析结果。
12. As a 质量看护人员, I want 访问深页和末页, so that 我能查看完整匹配结果。
13. As a 质量看护人员, I want 查看均值和比例的净影响, so that 我能理解对象对整体差值的算术贡献。
14. As a 开发人员, I want 从文件关联到函数和问题记录, so that 我能取得定位证据。
15. As a 开发人员, I want 分别查看两侧重复组与片段, so that 我不会误将跨版本组号视为身份。
16. As a 开发人员, I want 查看超大目录的扫描可见成员, so that 我能理解目录变化及覆盖限制。
17. As a 开发人员, I want 复制路径和可用位置, so that 我能在现有代码工具继续排查。
18. As a 阅读者, I want 区分无变化、未知和匹配歧义, so that 不确定数据不会被解释为确定结论。
19. As a 阅读者, I want 快速切换条件后仅显示最新结果, so that 旧响应不会覆盖当前分析。
20. As a 阅读者, I want 下钻返回后恢复分析上下文, so that 我能继续原来的任务。
21. As a 阅读者, I want 查询失败后按最新条件重试, so that 我能恢复分析。
22. As a 阅读者, I want 初始化失败时仍能阅读静态概览, so that 我能取得基础信息并知道交互不可用。
23. As a 内部验收人员, I want 使用固定版本和可复现流程核验真实输入, so that 正式交付有可信证据。

## Implementation Decisions

- 产品行为以最新 PRD、ARCHITECTURE 和已确认决策为准；FSR 提供历史背景，不恢复已被覆盖的要求。领域术语沿用 GLOSSARY。
- 保留现有 `generate`、`validate`，新增 `report`；必填参数为 `--baseline`、`--current`、`--output`。可选元信息与 profile 遵循架构契约。
- 构建入口为 `build_report(BuildRequest) -> BuildResult`。正常、受限、构建失败、参数错误及中断退出码分别为 `0/3/1/2/130`。
- Python 负责严格读入、适配、匹配、完整聚合、关联与保留判定；浏览器查询已编译结果。
- 按输入、分析、保留、封装、构建及浏览器存储、查询、状态、视图划分职责，不增加通用插件框架。
- 采用版本化 manifest、字典、列式块和关系索引；独立 gzip/base64 内嵌。Blob classic Worker 执行按需解压、完整查询、稳定排序和分页，使用 transferable 与按字节计费缓存。
- 默认完整保留明细及证据关系。若不能满足硬门槛，暂停评审，不自动裁剪或改变交付形态。
- 覆盖 13 类结果、20 项指标入口、12 项净影响及计算过程数据，沿用已确认三页交互。
- 比较、分类、筛选及排序使用未舍入数值；业务浮点展示使用十进制 Half-Up 两位小数。未知和不适用不补零。
- 临时产物完成检查后原子发布；禁止覆盖输入，替换既有输出需要显式 `--force`。
- 正式入口不依赖原型生成器或压力数据 manifest；运行资产随安装包分发。
- 只注册有核验证据的真实 profile。真实输入契约尽早内部核验，正式产物的业务及性能由 P4 终验。

## Testing Decisions

测试边界已获用户确认：以正式 CLI／构建入口生成 HTML，再通过浏览器完成业务任务为主验收边界；辅以分析、编解码和 Worker 查询接口测试。

- 验证外部行为、结果与不变量，不复制实现步骤。
- 复用 15 组 Golden、独立完整序列 oracle、有理数预期及原型缺陷回归，将其重新绑定正式产物；不得修改预期来迁就实现。
- 输入与分析覆盖重复键、缺失、空值、profile、身份歧义、扫描集合进出、严格阈值、目录覆盖及诊断传播。
- 数值覆盖 Half-Up、微小非零变化、零分母、安全整数边界及净影响守恒；交换两侧后按既定公式重新计算净影响。
- 格式与查询覆盖往返、损坏块、未知版本、跨块引用、完整计数、稳定排序、首／深／末页及 50／51 页边界。
- UI 覆盖快速切换、乱序响应、取消、重试、上下文恢复及复制失败。
- 安全与发布覆盖断网、注入、禁用脚本、初始化和运行失败、目标冲突、中断、写入失败、体积超限及安装包资源。
- 每侧 100k 文件／1m 普通函数，覆盖现有十组分布，补充长字符串、高函数密度、近全量集合进出及 deep 净影响直接核验。
- 在登记的 macOS／Chrome 版本验证 headed、真实双击及断网 `file://`；补齐 RSS 和 DOM 证据。

| 正式门槛 | 要求 |
|---|---:|
| HTML 体积 | ≤ 200 MiB |
| 概览可操作 | ≤ 10 秒 |
| 常用交互 P95 | ≤ 1 秒 |
| 重操作 P95 | ≤ 3 秒 |
| 浏览器新增峰值内存 | ≤ 2 GiB |
| 完整生成时间／峰值内存 | ≤ 10 分钟／8 GiB |

冷热采样分开，热查询每任务至少 20 次；保存逐次样本、环境版本、源码及产物摘要、内存和错误日志。硬门槛失败阻止对应关卡通过。

## Out of Scope

重建原型、重新选择 UI、默认重开架构；Windows／Edge 支持；200k／2m 强制验收；在线服务、多文件交付、历史趋势、Excel 输入、额外导出；源码读取、自动归因、重命名追踪、同名函数猜测配对；默认裁剪与静默降级。
